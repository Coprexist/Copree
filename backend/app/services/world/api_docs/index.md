# 群视界 API 文档总览（index）

> **读者**：群视界机器人（世界默认 AI）与编写世界代码的开发者
> **版本**：v1.0 ｜ **日期**：2026-08-05
> **接口规范**：RESTful + JSON，认证统一 `Authorization: Bearer <JWT>`

本文档按**功能分区**组织。每个分区只在此给出**区名与区介绍**，详细 API 在分区文档中；**AI 用 `view_api_doc` 工具按需打开分区**，人类开发者直接阅读 `sections/` 目录。

## 给 AI 的使用方式（重要）

1. 你的工具列表里有 **`view_api_doc`**：传入区号（`01`~`10`）即可查看该区的完整详细 API。
2. **先看区介绍再开区**：上表已给出各区介绍——判断你要做的事落在哪个区，只打开需要的区，不要一次全读。
3. 常见对应关系：
   - 建网页/改代码 → **03 文件操作**（必要时 06 页面与资源）
   - 套用现成 UI 组件 → **04 积木体系**
   - 在群里发言/管群 → **05 群聊 API**
   - 需要知道当前用户/群编号 → **01 世界编号变量**
   - 遇到报错 → **08 错误与安全**
   - 改完文件 push 报「无变化」/ pull 报「pulled N 无变化」/ 页面操作 429 → **10 同步与限流机制**

## 给开发者的阅读方式

- 分区详细文档：`sections/01-*.md` … `sections/08-*.md`（与 AI 通过工具读到的是同一份）
- 运行时目录：`data/world_api_docs/`（后端 `view_api_doc` 工具读取的位置，改文档即时生效，无需重启）

## 快速上手（给 agent 的 6 步）

1. 了解自己的身份与注入变量 → 打开 **01 世界编号变量**
2. 建立世界主页 → 打开 **03 文件操作**，写 `index.html`（+ css/js），`file_write` 自动建目录
3. 想套现成 UI → 打开 **04 积木体系**，`list_world_blocks` → `view_world_block` → `apply_world_block`
4. 用户从群聊进入世界后，你想在群里说话 → 打开 **05 群聊 API**，`send_group_message`（默认发到绑定群）
5. 用户手动改了代码 → 对话开始时读 **07 懒通知**，回复中体现"我看到你改了 xxx"
6. 随时改布局/加功能 → 继续写文件，保存即生效；报错查 **08 错误与安全**

## 界面硬性要求（每次创建/修改页面都必须遵守）

1. **必须适应手机（竖屏横屏都能玩；不锁定方向，也不要求单独做横屏版）**：竖屏 320px 窄屏下不溢出、可操作、可读（字号不小于 12px，可点击目标不小于 44px）；横过来是矮视口（约 844×390），布局要跟着变——用 `@media (orientation: landscape)` 与 `max-height` 调布局（顶部信息收紧、按钮横排、画布按短边缩放），底部操作区/输入框/关键按钮必须始终在可视区内（页面设了 viewport-fit=cover 的，横屏用 env(safe-area-inset-left/right) 避开刘海）；高度用 `100dvh`（不要 `100vh`：手机浏览器地址栏会吃掉底部，横竖屏都会）。
2. **必须直接前端化整个界面，操作和视图渲染都要前端化**：
   - 视图渲染前端化：界面就是 HTML/CSS/JS 前端页面本身，页面 DOM 由前端 JS 渲染，不依赖后端渲染模板；
   - 操作前端化：页面操作（点击/输入/状态切换/局部更新）在前端直接完成，能前端处理就不走后端；需要后端数据/持久化时才调接口（相对路径 fetch 或受控数据 API，06 分区）。
3. **操作绝不借道群聊**：页面上的每个按钮/入口都要有直接的点击反馈（前端直接执行或调事件通道），**禁止写「从群聊进入/群内直接发指令：探索 战斗 商店…」这类引导文案**，禁止让用户离开页面去群里发指令才能操作；页面操作一律走事件通道（06 分区 4.1，`POST /world/{id}/api/event`），世界程序回复用 SSE 状态（`publish`）。只有真正关键、需要别人在群里看到的事件（如宣布重大结果、求助他人）才用群消息 API。
4. **全屏**：平台支持全屏——沉浸页顶栏有全屏按钮；页面自己也可以加一个：按钮里调 `document.documentElement.requestFullscreen()`（平台 iframe 已授权 `fullscreen`）。棋盘/卡牌/地图/游戏这类沉浸内容建议提供全屏按钮，配合横屏体验最好。
