# 08 错误与安全
> 错误体格式、状态码表、认证要求、写操作身份与防护约定。

## 1. 错误体格式（统一）

所有错误返回 JSON：

```json
{ "detail": "错误描述" }
```

工具调用失败时返回：
```json
{ "success": false, "error": "错误描述" }
```

**看到 `success: false` 就按 `error` 调整**，不要盲目重试同参数。

## 2. 状态码表

| 状态码 | 含义 | 常见场景 |
|--------|------|----------|
| 400 | 参数错误 / 越界路径 / 非法类型 | 路径含 `../`、文件类型不在白名单、参数缺失 |
| 401 | 未认证（token 缺失/过期） | 未登录、登录态过期 |
| 403 | 无权访问 | 非创建者、非群管理员/群主 |
| 404 | 世界/文件不存在 | 路径写错、世界被删 |
| 422 | 参数校验失败（必填参数缺失/类型错误） | 少传了必填参数；若报 `local_kw` required 而你没传过这参数，是后端依赖注入 bug 的特征（`Depends(sessionmaker)`），联系管理员 |
| 429 | 限流 | 请求过频，稍后重试 |
| 5xx | 服务端繁忙/异常 | 稍后重试 |

## 3. 认证要求

- 所有请求必须带 `Authorization: Bearer <JWT>`。
- 实例收到任何 API 请求**第一件事就是验证用户信息**（JWT），世界代码的写操作**以触发它的用户/AI 身份执行，不可伪造**。

## 4. 防护约定（平台侧已强制，你无需实现）

| 防护 | 说明 |
|------|------|
| 路径越界 | 世界文件只允许在 `data/worlds/{id}/` 内，`../`、绝对路径、符号链接逃逸一律拒绝 |
| 类型策略 | 允许清单之外一律拒绝；**可执行/安装包/宿主脚本**（`.exe .msi .dll .bat .sh .ps1 .jar .apk .iso` …）创建即拒且会被兜底强删（清单见 03 分区 1.1） |
| 下载落点 | 下载一律落在 `downloads/`，且只能访问公网地址（内网/本机拒绝） |
| 内容红线 | 下载拦截色情/暴力/违法内容：链接、目标文件名、文本正文三处查，命中即失败且不落盘 |
| 大小上限 | 单文件 32MB |
| 身份校验 | 群管理操作（改角色/踢人）仅群主/管理员可调用 |
| 管理权限 | `set_group_member_role` 仅群主；`kick_group_member` 群主/管理员，不能踢自己/群主 |

## 4.5 安全边界（平台强制，你无需也无法绕过）

| 边界 | 说明 |
|------|------|
| 文件系统隔离 | 文件工具只能访问 `data/worlds/{id}/`（自己的世界目录）。**平台代码区、接口文档目录、其他世界目录一律不可达**——`../`、绝对路径、符号链接逃逸全被拒绝（400） |
| 文档获取通道 | 接口文档**只能**通过 `view_api_doc` 工具读取（服务端白名单代读，仅 01~10 注册分区）。文件系统里没有文档副本，**不要尝试用文件工具找文档**（也找不到） |
| 沙箱（代码执行） | `run_world_code` / 世界侧 skill 在 Landlock 沙箱内执行：世界目录可读写、skill 目录只读，**其他路径全部 EACCES**；无网络、超时强杀 |
| 能力最小化 | skill 的 `ctx` 只包含 manifest.permissions 声明过的能力——没声明 `file` 就没有文件对象，声明了也只在世界目录内 |
| 身份不可伪造 | 世界代码的写操作以触发它的用户/AI 身份执行，JWT 在平台侧校验，世界侧无法伪造 |

> **原则**：平台代码、其他世界、系统资源对你是不存在的。需要什么能力走平台工具（文件/群聊/文档/记忆），不要尝试路径探测或绕过——也没有路径能绕。

## 4.6 运行模式门禁（自动 / 审阅 / 计划）

世界有一个由**用户设置**的运行模式（记在 `worlds.config.sessions[<会话>].ai_mode`，默认 `plan`），决定你自己能自主到什么程度。它**跟着对话走**：同一世界不同会话可能是不同档，你只受当前这场会话的约束。你**没有工具能改它**——这是用户对你的约束。

| 模式 | 你的下载 / 删除 / 改动机制 | 你会看到什么 |
|------|---------------------------|--------------|
| `auto` 自动 | 平台不打断，直接执行 | 工具正常返回 |
| `review` 审阅 | 平台弹窗请用户确认后才执行 | 工具可能等几秒到几分钟（用户在看弹窗），然后执行或失败 |
| `plan` 计划 | 动手前必须先 `present_plan` 并让用户通过 | 计划通过前：`{"success": false, "error": "计划模式：本轮计划还没通过…"}` |

- 审阅模式下**同类操作本轮只问一次**：用户同意过一次下载，本轮后续下载不再弹窗。
- 被拒时的返回：`{"success": false, "error": "用户没有同意本次…", "blocked_by": "ai_mode"}`。**这是用户的决定，不要换工具、换路径、改参数重试**——停下来问清楚意图，或按用户说的改。
- 「改动机制」指用户没说、你自己判断要改的，或与用户先前说法有出入的改动。用户明确叫改的也照常调工具（平台仍会弹一次确认，但同类本轮只弹一次）。
- 需要用户拍板别的事（选方案、确认理解）用 `ask_user`（事件类型关键词必填：`download/delete/modify/other`）；计划模式下用 `present_plan` 提交计划。两者与平台门禁**共用同一条弹窗通道**。
- 计划可以带**预计工具轮次**：\`present_plan(plan, tool_rounds=N)\`——本轮默认上限（世界配置 \`max_tool_rounds\`，默认 50，硬上限 200）不够时用它申请提额，
  用户批准计划即同时批准提额（计划被否则不生效）。
- 计划可以**分成条目**：`present_plan(plan, items=[\"改标题\", \"加按钮\"])`。用户在弹窗里点「同意」= 整份通过；
  也可以只勾其中几条——那时工具结果给你两张单子：`approved_items`（做这些）、`skipped_items`（没通过，**一条都别做**）。
  别把「部分通过」当成整份驳回，也别自己把没勾的补上。
- **用户不吭声怎么办**：自动档下你的 `ask_user` 等 10 分钟，没人回就按「用户未回复」返回并**允许你按自己的判断继续**（在回复里说明决定）；审阅/计划档下没回复一律按「不通过」处理——不要反复追问同一个问题，也不要把"没回复"当成默许。

## 5. LLM 友好错误（世界对话层）

世界 AI 对话遇到 API 错误时，系统会转成友好提示：

| 场景 | 提示方向 |
|------|----------|
| 402 余额不足 | 引导充值（已记录工作流，充值后说「继续」可接着做） |
| 401/403 密钥问题 | 提示换 Key |
| 429 限流 | 稍等重试 |
| 5xx | 服务繁忙，稍后重试 |

**你该做的**：遇到 402 时向用户说明"余额不足，充完说继续"；其他错误如实转述并给出下一步。

## 6. 工具使用纪律

1. **别把工具调用原始内容写进回复文本**——直接说你要做什么/做了什么。
2. **先读后写**：改文件先 `file_read`，群聊先 `get_group_messages`，管理先 `list_group_members`。
3. **温和去重**：重复调用同一工具且结果一致会被提示「⏭ 已跳过」——那是系统在帮你省 token，不是错误；结果变了会正常返回。
4. **工作流记忆**：对话中断（无最终回复）时，系统记录已完成工具；下次对话会注入【未完成工作流】提示，说「继续」即可接着做，不要重做。
