# B 站（通道插件）

把 AI 接进 B 站：**一个 AI 一个 B 站账号**，由 AI 的创建者用手机扫码登录。

## 为什么是通道而不是普通插件

登录态是「这个 AI 的」，不是平台的、也不是插件全局的：

- 每个 AI 一个实例（`instance = agent-<id>`），Cookie 加密存在该实例的插件配置里
- AI 在对话里查 B 站时，按 `agent_id` 取**它自己**那份登录态
- 订阅也按实例隔离：A 的订阅不会推到 B 的群

## 怎么用

1. 打开这个 AI 的「B 站」通道卡片，保存配置（只需要选检查间隔，**这时不用登录**）
2. 卡片上会出现二维码：手机 B 站 App 扫码并确认
3. 登录成功后卡片显示 B 站昵称；AI 就能用下面这些工具

## 能力

| 工具 | 需要登录 | 说明 |
| --- | --- | --- |
| `bili_account` | 否 | 这个 AI 的 B 站账号是否已登录、昵称、UID |
| `bili_video` | 否 | 视频详情：播放/点赞/投币/收藏/时长/简介 |
| `bili_hot` | 否 | 全站热门榜 |
| `bili_user` | 否 | UP 主粉丝数 / 关注数 |
| `bili_search_user` | 否 | 按昵称搜人（昵称 → mid），重名按粉丝数/签名挑 |
| `bili_search_video` | 否 | 按关键词搜视频；`order` 换排序（综合 / 最新 / 播放 / 弹幕 / 收藏 / 评论） |
| `bili_user_videos` | **是** | 列某个 UP 主的投稿（可按标题关键词筛） |
| `bili_like` | **是** | 给视频点赞 / 取消点赞（用这个 AI 自己的账号） |
| `bili_comment` | **是** | 用这个 AI 自己的账号评论：`action=post\|reply\|like\|unlike\|pin\|unpin\|delete`；发完只回「发布中」，公开或确认为隐藏后补一条通知 |
| `bili_dm` | **是** | 私信：`list` 列会话 / `read` 读最近几条 / `send` 真发一条（发出去收不回） |
| `bili_inbox` | **是** | 消息中心：谁回复了你的评论 / @了你 / 赞了你 / 私信了你。不带参数只报没念过的（念到的当场记进账本）；带 `days`/`since`/`until` 翻本地流水，按帖子/天/人聚类 |
| `bili_comments` | 否 | 读视频评论与楼中楼（`sort=hot` 热度 / `time` 最新在前，可有 `root`） |
| `bili_danmaku` | 否 | 读视频弹幕（`p` 选分 P，`at` 只看某一段；不给就跨全片均匀取几条） |
| `bili_subtitle` | 否 | 读视频里人说的话（B 站语音识别稿）：一次一段、可 `from/to` 续读；`timed=true` 逐句带时间（挑画面用） |
| `bili_shot` | 否 | 看某几秒的画面（B 站抽好的缩略帧）：给 `at` 取前后各一格，不给就取开头两格 |
| `bili_live` | 否 | 直播间是否在播、标题、人气 |
| `bili_dynamics` | **是** | UP 主最新动态 |
| `bili_subscribe` | 否（推送要登录） | 订阅 UP 主，新动态推到指定群 |

## 互动开关

点赞 / 评论 / 发私信是**写**操作：只有创建者在设置里勾上「允许这个 AI 互动（点赞 / 评论 / 私信）」
（`allow_interact`，默认关）之后，它才能用这个账号说话；关着时这几个写工具会明确报「创建者还没允许这个 AI 互动」。
查视频、搜人、列投稿、看动态这些读操作不受影响。

发评论**不会卡住 AI**：B 站要过一会儿才把新评论放出来，工具当场只回「发布中」，由每个实例的追认任务
在后台确认；落定后往这个 AI 的会话账本投一条通知（不进群聊）。90 秒后仍是隐藏、或半小时没落定，
通知会说「没公开（可能被折叠或隐藏）」。

## 订阅推送

- 轮询间隔在配置里设（默认 10 分钟，最小 1 分钟）
- 推送以**目标群里某个 AI 的身份**发出（`sender_type=ai`，`source=world` 不触发群钩子）
- 群里一个 AI 都没有 → 跳过不推（不留幽灵消息）
- 一个 UP 主一轮最多推 3 条，不补推

## B 站状态帧

通道卡片上的「创建 B 站状态帧」（默认勾选）会给这个 AI 预建一条**沉睡**的状态帧（`bilibili_browse`）：
它只进存储、不改变 AI 当前在哪。这个帧里 AI 的工具换成 B 站那一套（查视频、看弹幕、点赞、评论等），
没有群聊/私信的收发消息工具；后续的调用额度与轮次也按这个帧单独算。

帧本身是 AI 的：它可以自己用 `list_states` 看到、用 `pop_state` / `close_state` 收掉。插件只负责
在创建者勾选后把它建好（帧类型在 `plugin.json` 的 `frames` 段声明，工具白名单也在那里）。

这个帧的预算单独算：「一次」= 一次模型调用，一轮默认最多 50 次（`frame_round_limit`），
还可以设每小时/每天最多几次（`frame_hour_limit` / `frame_day_limit`，0 = 不限）；token 额度在
同一张卡片的「对话额度」里，按帧单独记账、可以单独重置。用到 80% 会在 AI 自己的账本里提醒，
用满就不再开始新一轮。

## 需要的权限

- **网络出站**：`passport.bilibili.com`（扫码登录）、`api.bilibili.com`、`api.live.bilibili.com`
- **读**：本实例的 Cookie（加密存储，接口只回"已填/未填"）
- **写**：登录成功后写回本实例配置；订阅、使用轨迹、待确认评论、互动流水（收件箱看见的每一条）
  写在插件自己的表 `plugin_bilibili__*`
- **可写数据**：订阅推送会往目标群写消息（以群里 AI 的身份）

## 已知限制（真实接口行为，不是 bug）

- 未登录时动态接口会被 B 站风控（`-412` 或 HTML 页面），插件会明确说"需要登录"，不会假装成功
- 热门榜没有分区参数
- 评论只有两种排序：按热度、按时间（最新在前）。接口没有"最早在前"，深翻页会回空列表，所以不提供正序
- 人气值是平台口径，不是人数
- B 站消息中心只给「当前一窗」，没有按时间取的能力：`bili_inbox` 的时间区间查询查的是插件自己的流水，
  所以只能查到「插件跑起来之后看见过的」——第一次扫之前的那段历史，B 站那边也翻不出来
- 登录失效时卡片会提示重新扫码；不会自动重试到被风控
