# 记忆与拟人化：本仓 vs DSH 生态 / AstrBot / 开源记忆系统

> 对比日期：2026-11-01
> 对象：本仓工作区（FastAPI 后端）；DSH 0.2.1-rc.3（306 个包，其中 `dsh-*` 295 个）；DSH 插件市场 8107 条（awesome-dsh-plugin.com 目录，2026-10-31）；dsh-mneme 0.9.3；AstrBot 本体与插件生态；Mem0 / Zep / Letta / Memobase / MemU / A-mem / Cognee；SillyTavern 与 dsh-NextTavern。
> 证据口径：**代码实读 > 线上实测 > 官方文档 > README 声称 > 未验证**。凡属判断，都标置信度；凡未做，直接写「未做」。

## 0. 一页结论

### 0.1 可验证的事实（不掺判断）

| # | 事实 | 证据 |
|---|---|---|
| 1 | DSH 内置 295 个 `dsh-*` 包里**没有跨会话长期记忆**；`dsh-persona` 只是两段提示词模板 | 包清单 + README |
| 2 | DSH 市场 8107 条中，记忆类 352 条；拟人向关键词命中：人格 221、情绪 60、桌宠 182、语音 199、表情 54、主动 184、打字/撤回 265、角色扮演 30 | 目录统计（关键词，非精确分类） |

### 0.2 判断（有争议，按样本给）

1. **记忆工程：我们对 DSH 市场属「中下」，对 AstrBot 生态属「中上」。** 依据是写入/巩固/检索/审计/评测五处的完成度，不是功能数量。
2. **拟人化：我们强在「结构」和少量「门控」，弱在「内容」和「表现」；没有真正的「状态→行为」闭环。** 情绪是备注，意愿是几乎不触发的保险丝，状态链是脚手架。
3. **DSH 市场的拟人主要停在表现层与提示词层，行为层只有 4 个例外**（feiyu-mood、mind、aurabot、identity）；AstrBot 是「器官齐全、没有内分泌」，记忆中位工程水平偏低；角色扮演生态的记忆是「为沉浸感服务的检索」，无重要性/冲突/遗忘。
4. **我们真正可辩护的独有项只剩 4 条**：焦段、指纹账本、状态链这个结构、按调用次数的主观时间。意愿评分与「缓存友好」都已被样本里的其他实现覆盖。

### 0.3 一句话

**记忆向 mneme 学工程，拟人向 private_companion 学「内容」、向 identity/aurabot 学「状态→行为」，表现层向 DSH 市场学「皮」；我们守住「焦段 + 账本 + 状态链」这三样结构性东西，并且必须补上「可证明」。**

## 1. 概念框架：四层 + 三条判据

### 1.1 四层，而不是「机制 vs 剧本」二分

| 层 | 作用 | 本仓实现 | 是否改变行为 |
|---|---|---|---|
| **门控 gate** | 决定要不要叫模型、给哪些工具 | DND/静音/限流、意愿阈值（`decider.py` Gate 5）、帧级工具白名单 | **是**，但窄且硬编码 |
| **结构 structure** | 组织上下文，让模型更容易一致 | 状态链/交接、记忆账本、焦段索引 | **否**，只改「模型看到什么」 |
| **内容 content** | 人设文本、日程、日记、世界书 | 人格锚点/人格段、记忆正文 | 间接 |
| **表现 skin** | TTS、立绘、桌宠、表情、格式 | 表情包、连发、延迟/typing | 只影响观感 |

**关键区分**：
- 剧本化 = 作者写**事件**（第几天、什么天气、哪条日程）；
- 结构化 = 作者写**法则**（状态怎么更新）；
- 但两者都仍是程序。**「机制」不应被用来暗示「生命」**。
- 真正决定行为的链路是：门控（平台）→ 模型（`end_turn` / 工具调用）→ 门控（工具白名单、限流）。**主动权在模型，平台只设边界。**

### 1.2 三条可检验判据（代替「像不像人」）

1. **非预写性**：作者没写过的场景，系统能否给出自洽反应？
2. **路径依赖（限定版）**：同一人格、两段经历，面对同一句话，**知识/关系/情绪**可以不同，但**价值观、说话风格、身份**不能变；差异必须能追溯到具体记忆/状态，而不是「换了一个人」。
3. **一致性成本**：跨时间自洽有代价（要维护记忆、状态、关系）；不能随便重置，才有「主体感」。

对应的实验是**反事实回放**：同一人格，喂两段历史（A：被反复叫醒、被夸；B：睡得好、被冷落），再问同一句话。若差异能归因到状态与记忆，机制在起作用；若几乎一样，就只是「剧本 + 额外步骤」。**本仓尚未做这个实验。**

### 1.3 本仓的实测：三个「机制」其实都不是

- **情绪**：`update_emotion` 只写状态帧；`emotion_to_text` 只进摘要；全仓没有一处读取情绪去改门控、工具、延迟或表达。**它是给模型看的参考。**
- **意愿**：`decider.py` Gate 5 有阈值，但基础分 50、阈值 20、被 @ 永不拦截。线上 719 条 `decision=` 记录里「意愿不足」**0 次**；`priority` 只写日志，无仲裁用途。**它是几乎不触发的保险丝。**
- **状态链**：交接 + 工具白名单。**它不决定要不要回、也不决定怎么回**；本质是上下文结构。

**结论（置信度高，属定义问题而非效果问题）**：我们做的是**门控 + 状态结构 + 上下文工程**，不是「状态驱动的意志」。要让情绪/关系成为机制，必须把它们接进「是否行动、怎么行动」的判定，并以日志验收（「因情绪/关系被拦下」次数 > 0）。

### 1.4 为什么仍然值得做结构

- **非预写性**：结构让模型能处理作者没写的处境；
- **路径依赖**：记忆/状态/焦段让「同人设、不同经历」产生差异；
- **一致性成本**：状态与记忆一旦重置，角色就变了——这是产品可感知的，不需要证明「生命」。

---

### 1.5 情景差异 ≠ 人格漂移（这条最容易误读）

「同人设、不同经历产生差异」听起来像「AI 会变成不同的人」，这确实是坏的。要把两种差异分开：

| | 该不该有 | 例子 | 我们的护栏 |
|---|---|---|---|
| **情景差异** | **该有** | 在群里简短、在私信里话多；工作时只开文件工具、闲聊时开社交工具；对熟人提旧事、对陌生人客气 | 状态链 + 工具白名单 + 焦段 + 记忆 scope |
| **人格漂移** | **不该有** | 换个人聊就换一套价值观；同一句话今天温柔明天刻薄；把别人的私事讲给群里 | 只读人格锚点 + 一致性系数 + 「别串台」交接 + 私信/群记忆隔离 |

换句话说：**要的是「同一个人在不同情景下的不同表现」，不是「不同的人」。** 人在公司、在家、对朋友、对陌生人，本来就不一样；但价值观和说话方式不会换。我们的状态链/焦段/记忆 scope 服务的是前者；人格锚点服务的是后者。

这也回答了「专注当前、更沉浸」：状态链的交接尾巴明确写「不要在当前会话回应它、不要复述」，焦段决定「哪些记忆够得着」，记忆账本只在变化时补一条——目的都是**把当前场景收窄，同时不丢长期**。真正的风险不是「有差异」，而是**差异没有边界**：记忆把 A 群的事带进 B 群、情绪把上一段的火撒到下一段、人格被经历改写成另一个人。

### 1.6 我们目前有没有这个问题

- **设计意图**：没有。每个 AI 是独立 agent，有自己的锚点、记忆、状态链；不是「一个 AI 对所有人格分裂」。
- **实现现状**：有边界，但护栏是「软」的——
  - 人格锚点只读，AI 改不了（`routers/brain.py:154`），这是硬护栏；
  - 交接尾巴有「别串台」的文字约束，但这是提示词层面的软约束；
  - 记忆 scope 有 private/group 之分，但焦段召回是「任一元素命中即召回」，跨情景泄漏要靠 AI 自己判断；
  - 没有「同一人格跨会话输出一致性」的检查或评测。
- **结论**：方向对，强度不够；要做的是把「人格不变量」写死（身份/价值观/风格），把「可变状态」限定在知识/关系/情绪，并用反事实回放验收：两段经历带来的差异，必须能解释为「她知道得更多/关系更深」，而不是「她变了个人」。

### 1.7 最要命的一种「漂移」：只在本场景记得自己

用户指出：跨情景泄漏无所谓（都是他自己），**真正难受的是「他在别处干过什么，换个场景就忘了」**——只有站在具体场景里才记得，这才是人格漂移。这个判断比「人格漂移」的通常定义更准：不是价值观变了，而是**自我经历的连续性断了**。

**我们的项目有没有这个问题？有，而且是默认行为。** 证据链：

1. **写入侧默认把记忆锚在当前会话**：`focus_service.resolve_anchors` 在 `session_foci` 与 `semantic_foci` 都为空时，把 `session_refs` 物化为 `[当前会话]`（`services/agent/focus_service.py:162-183`）。也就是说，AI 在 A 群随口记下的事，默认只属于 A 群。
2. **读侧按锚点过滤**：`memory_reach` 只有在当前 `context_ref` 命中 `session_refs`、或命中所属会话焦段/语义焦段时才返回 >0（`utils/pure/focus.py:247-275`）。锚在 A 的记忆，在 B 里够不着。
3. **群共享记忆只属于那个群**：`recall_relevant_memories` 在群聊里召回 `private` + **当前群**的 `group` 记忆（`memory_service.py:182-201`）；A 群的 group 记忆不会出现在 B 群。
4. **状态链只带当前帧 + 交接尾巴**：摘要只渲染当前帧与本次 `handoff`/`completed_handoff`，其他帧只报「另有 N 帧未完成」，不展开内容（`state_stack.py:485+`）。交接尾巴最多 4 轮原文，一次性。
5. **全局检索存在，但要 AI 主动想起**：`list_states` 能看到所有帧的 id/type/task/todo/status；`search_messages` 能按关键词搜「已加入的群与参与的私信」。两者都是**按需工具**，不自动进上下文。

**结论**：自动召回层面，这个问题**几乎必然发生**（记忆默认场景化、跨场景够不着）；手动层面有补丁（`list_states` / `search_messages` / 交接尾巴 / `cross_state_note` 40 次调用内有效），但要求 AI 先意识到「我该去查」。**这不是「偶尔忘」，是默认架构把「自我经历」也当成了「本场景私有」。**

**根因**：我们用同一套 `scope` + 锚点同时表达两件不同的事——
- 「**我做过什么**」（自我经历，应该跨场景连续）；
- 「**别人告诉过我什么**」（他人隐私，应该按会话/群隔离）。

这两件事被塞进一个字段，默认值只能二选一，于是自我经历被牺牲掉了。

**修法（建议，未实施）**：
1. **按归属分轴**：`self`（我的行动、我的安排、我的承诺）默认全局；`other`（他人事实、群内事务、私信秘密）默认场景/群。
2. **加一条全局「经历索引」**：每个场景结束/切换时写一行「我在[场景]做了[事]」（不含隐私内容），作为常驻的轻量索引；细节仍按需查。这样 B 场景里至少知道「我在 A 做过什么」，而不是完全空白。
3. **改默认锚点**：`event/relationship/promise` 这类自我经历默认锚「所有聊天」；只有明确关于他人的才物化到当前会话。
4. **验收**：A 群做一件事 → 切 B 群问「你刚才干了什么」→ 必须答得出（可只给概要，不带 A 的隐私细节）；答不出即判失败。

### 2.3 三条口径

1. **星数归属**：市场目录里的 stars 多数是**母仓**（hindsight 56.7k、OpenViking 41.2k、MemOS 12.2k 都是母项目），不能用星数证明适配插件质量。
2. **关键词不是分类**：情绪/桌宠/语音等计数是描述关键词命中的上限估计，会混入无关词。
3. **平台 vs 插件**：本仓是多用户、多群、多 AI、带世界/文件/插件系统的平台；DSH 是单用户本地编码 agent 运行时；AstrBot 是 IM 机器人框架。「按用户隔离」这类能力在 DSH 插件里普遍不存在，是宿主没有多用户概念，不是做不到。

## 3. 本仓事实基线

### 3.1 记忆

**数据模型（代码验证）**
- 双层：`rough_memories`（标题 + 标题向量 + 权值 + 类型 + 可见范围 + 三组锚点 + 最近召回时间/调用计数）↔ `detail_memories`（正文）。`backend/app/models/memory.py:12-60`
- 结构记忆 `structured_records`：`category/sub_key/field → value` 目录树，同样带类型、权值、锚点。
- 类型按陪伴定位：`person/relationship/promise/event/preference/daily`，默认权值 5/5/4/3/3/1（`utils/pure/memory_weight.py:32-38`）。
- 权值两层：写入时 1-5 + 读取时现算时间权值：

  ```
  T = max(Δ天, Δ调用 × 30 / 200)
  时间权值 = 1 / (1 + T / 30)
  有效权重 = (设定权值 / 5) × 时间权值
  ```

  阈值 0.1；权值 1 跌破即物理删除，≥2 只是不再注入（`memory_weight.py:24-89`）。
  **实算**：权值 5 静默 30 天 = 0.5；权值 2 静默 90 天 = 0.1；权值 1 静默 30 天 = 0.1（删除档）。

**写入**
- 显式：`store_memory` / `manage_records` / `forget_memory`。
- 自动：正则触发器（记住/偏好/决定/个人信息/任务/目标）→ 入队 → 批量落盘（`memory_service.py:626-704`）。
- **无 LLM 抽取、无会话结束蒸馏、无每日反思。**

**注入**
- 账本条目 `mem:<id>@<内容指纹>`：第一次投全文；指纹不变不再投；改过补「以它为准」；位置在当轮新消息之前（`memory_delivery.py`、`memory_entry.py`）。
- 指纹 = 标题 + 正文 + 锚点，不含时间戳/权值，避免衰减/召回计时造成假更新。
- 记忆索引（结构树 + 知识库）走版本链冻结，放锁定段（`ai/llm.py:939-975`）。
- 单条注入上限 300 字，截断带省略号。

**检索**
- LIKE（中文 2-gram 滑窗、标题优先）+ 向量补位，top_k=5（`memory_service.py:43-130, 276-430`）。
- 焦段过滤 `_apply_reach`：按会话/会话焦段/语义焦段判「够不够得着」，够不着丢弃、命中多的排前。
- **无 BM25/FTS5、无 rerank、无图检索。**

**整理**
- 每日：权值 1 且有效权重跌破阈值 → 物理删除；`pending_archive` 同名合并、独特转正（`tidy_service.py`）。
- **无冲突裁决、无聚类合并、无「记忆库摘要」生成、无审计表。**（「记忆库摘要」指对记忆库整体生成总览，区别于 compact 的上下文摘要）

**可运维**
- 有记忆管理前端与「灵魂档案 2.0」导出/导入；**无 MCP/CLI/独立 API/daemon**。

### 3.2 拟人

**人格**

### 5.3 公约数

1. 本地优先、可检视（SQLite/Markdown）。
2. 自动注入 + 硬预算（800 字符到 8000 字符、2000 字符/层、25KB）。
3. **前缀缓存意识是共识**：meow/fish/engramory/evolve/memento/automem 都做稳定段+动态段；fish 有实测注释。
4. 项目/workspace 是默认边界；per-agent/user 硬隔离只有 memento。
5. 后台巩固：meow dream、reme auto_dream、MemOS L2/L3、hindsight consolidation、fish 衰减、automem reflection。
6. 工具面 + 设置页是标配。

### 5.4 几乎没人做的七件事

1. 真正的冲突裁决/真值维护；2. 系统化写入质量闸门；3. usage→value 反馈闭环；4. 硬隔离/多用户；5. 跨插件协议（memento `dsh-memory-protocol v1` 是唯一尝试）；6. 公开评测；7. 删除/遗忘语义。

### 5.5 宿主带来的独特做法

- `section`（静态）vs `context`（动态、缓存友好）；选错就是缓存灾难（fish 实测）。
- 注入消息带 `source.form: recall/snapshot/instructions`，UI 区分「召回材料」与用户输入。
- compaction 是一等事件：engramory 压缩前提醒保存、meow 压缩后重注入、automem 用 handoff 替代。
- subagent 当记忆维护 worker。
- `session.header.cwd` / `sessionPersistence` 直接给项目作用域。
- `approval` 服务：memento 的写审批是最佳复用例。

### 5.6 天花板

DSH 没有正式记忆 API/事件类型，插件各造轮子；预算与缓存把记忆压成每轮几百到几千 token 的提示词工程；几乎无闭环评测与冲突裁决。**短期上限是「很好的个人助理记忆」。**

### 6.1 三条收敛做法

- **注入只剩两条 API**：`systemPrompt.section()`（稳定前缀）与 `systemPrompt.context()`（每轮追加、为保缓存）。社区软约定：`dsh-mind` 读别人的 `whale-persona/config.json`，发现外部在管人设就自己不注入——人格被当单一所有权资源。

### 6.3 表现层最成熟，但与模型脱节

### 6.5 为什么

DSH 是回合制编码 agent：心智单位是 turn/step，扩展点只有 systemPrompt 与 tools，**没有世界时钟**；主动只能靠宿主闹钟或前端 `setInterval`。于是拟人 = 提示词 + 前端动画 + 私有状态文件。

## 7. AstrBot

### 7.1 本体：器官齐全，没有内分泌

- 人格：SQLite `personas`（`system_prompt/begin_dialogs/tools/skills/custom_error_message/folder_id`），绑会话 `ConversationV2.persona_id`；拼装 = Persona Instructions + few-shot + 工具/技能白名单 + workspace EXTRA_PROMPT.md。

## 9. 角色扮演生态（代码级）

- **SillyTavern 官方栈没有长期记忆扩展**：15 个内置扩展里 `extensions/memory` 实际是 Summarize、`extensions/vectors` 是 Vector Storage、`extensions/attachments` 是 Data Bank。三者共用注入口 `setExtensionPrompt(key,value,position,depth,scan,role)`，靠前缀抢位。
  - Summarize：摘要在 `message.extra.memory`，每 10 条/词数触发，200 词，depth=2 SYSTEM；编辑/重生会删摘要。
  - Vector Storage：400 字符切块、batch 5、collection=chatId；查询=最近 2 条，topK=3、阈值 0.25，最近 5 条不参与重排。
  - World Info：19 字段、8 种注入位置、扫描深度 2、预算 25%；**按关键词检索作者写死的条目，不会演化**。
- **角色卡 v2/v3 规范没有「记忆」字段**：人格是声明式静态文本，记忆只能靠内嵌 `character_book`（lorebook）。
- **商业产品**（证据弱）：C.AI 有 Memory/Lorebook；第三方描述 2026-05 的 Memory = Story Memory（手动 Pin）+ Facts（自动抽取）+ 用量仪表，不跨聊天继承。
- **中文开源**：Open-LLM-VTuber 每轮 append 全量历史、README 承认长期记忆移除；Fay 宣称未验证；kirara 无记忆条目。

**本质差异**：RP 记忆是「为沉浸感服务的检索」——写入人工或无脑全量，读取相似度/关键词拼 prompt，无重要性/冲突/遗忘。**RP 怕出戏，Agent 怕失实。**

## 11. 赢在哪、输在哪

### 11.1 可辩护的独有项（样本内，不是全行业）

1. **焦段**：记忆锚定「会话/会话焦段/语义焦段」，AI 自声明适用范围；空锚点物化，不存在隐式全局。最接近的先例是 SillyTavern World Info（按内容关键词触发，不是归属声明）。
2. **指纹账本**：`mem:<id>@<指纹>`，只补变化、改过补「以它为准」，对衰减/召回计时免疫。缓存友好与「不重复投」都有先例（meow/fish/memento），**独有的是更正语义**。
3. **状态链这个结构**：帧 + 交接 + 4 轮原文尾巴 + 工具白名单；样本内没有第二个栈。**但它是结构，不是行为机制。**
4. **主观时间**：用 API 调用次数当 AI 时钟，与真实静默取快者；同类都用真实时间半衰（feiyu 12h、mind 3–6h、fish 15–60 天、mneme heat）。

**不再列入独有**：意愿评分（identity/aurabot/AstrBot 都有近似物，且我们几乎不触发）、缓存友好（共识）、情绪衰减（feiyu/mind/identity）。

### 11.2 落后项（按严重度）

1. 写入质量（无 LLM 蒸馏/反思）；2. 巩固与冲突（无合并/裁决/聚类/审计）；3. 检索（无 BM25/rerank/图）；4. 审计与可运维（无 dream/recall 审计、无 MCP/CLI/API）；5. 关系/好感（无独立数值与演化）；6. 情绪无行为耦合；7. 内容层（无生活锚点）；8. 表现层（无 TTS/立绘/桌宠/识屏）；9. 表达细节（缺按字数延迟、概率已读不回、句末防抖、戳一戳、撤回联动）；10. 可证明性（无 benchmark）。

### 11.3 大家都没解决

- 记忆正确性无法证明（抽取丢信息、图会过时）；
- 巩固副作用（LLM 合并引入幻觉）；
- 人格与记忆的一致演化（只有「记忆影响提示词」，没有「经历改变性格」的可验证机制）；
- 情绪真实性（数值/提示词，无法外部验证）；
- 多用户/多角色隔离与共享边界（我们平台统一，反而更接近产品化）。

## 12. 建议（按 ROI，不立即动手）

1. **给自动记忆加 LLM 蒸馏/反思**（会话结束或空闲触发），复用权值/焦段，不引入新存储。
2. **记忆审计 + 可回放**（输入快照 hash、决策、逐条去向），先让改动可解释。
3. **检索补 BM25/FTS + 20–50 条固定集**（Recall@5/MRR），先能量化。
4. **独立好感度/关系状态**，并接进门控（负关系降低主动/提高门槛），用日志验收。
5. **情绪接门控**：愤怒提高回复门槛、精力低强制延迟、关系负值降主动概率；验收标准是「因情绪/关系被拦下次数 > 0」。
6. **最小生活锚点**：睡眠窗口 + 2–3 条日程 + 纪念日，只作为主动触发的输入；不碰日记/梦境/3D 房间。
7. **反事实回放实验**：同人格、两段历史、同一句话，测差异能否归因到状态/记忆。
8. **表达细节**：按字数延迟、概率已读不回、撤回取消在途生成（成本低、体感强）。

## 16. 附录 D：术语表（回答「这些是啥」）

| 术语 | 一句话定义 | 我们有没有 | 为什么重要 |
|---|---|---|---|
| **LLM 抽取** | 让 LLM 从对话里抽出结构化事实（谁、什么偏好、何时、关系），写成记忆条目 | 无（只有正则触发 + AI 主动调 `store_memory`） | 决定记忆的「写入质量」；没有它，只能靠模型自觉或关键词 |

| **MCP / CLI / daemon** | 把记忆做成独立服务：MCP 给任意 AI 客户端挂载、CLI 给脚本、daemon 常驻 | 无（只有平台内 REST 与前端） | 别的工具（Claude Code、脚本）能不能共用这份记忆 |
| **compact（上下文压缩）** | 把「当前会话窗口」的中间消息用 LLM 摘要，腾出 token；摘要回到本会话 messages | **有**（`context_compression_service.py`） | 省 token、扛长会话；**但它不是记忆蒸馏** |

### compact 与记忆蒸馏的区别（本仓现状）

| 维度 | compact（我们有） | 记忆蒸馏（我们没有） |
|---|---|---|
| 对象 | 当前会话的 messages | 整段会话/素材里「值得跨会话记住的事」 |
| 产物 | 一段自由文本摘要，拼回 messages 的 system 消息 | 结构化记忆条目（类型/权值/锚点/来源） |
| 去向 | 本会话上下文；会话清空/结束即消失（解锁时只用于重建账本摘要） | 记忆库（`rough_memories`/`detail_memories`），跨会话可检索 |
| 触发 | token 阈值（窗口压力） | 会话结束 / 空闲 / 定时 |
| 有无去重/冲突/类型 | 无 | 有（至少应有） |
| 代码证据 | `_request_summary` → `summary` 拼 `messages`；`stats.summary` 仅用于解锁写账本 | 无 `store_memory` 调用 |

**结论**：`compact` 是「LLM 摘要」，不是「记忆蒸馏」。它保证长会话不断片，但不保证「聊过的事以后还记得」。
