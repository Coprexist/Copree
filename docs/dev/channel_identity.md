# 通道标识与多实例身份

一个 Copree 群可以由**多台机器人**同时接着（QQ 官方通道一个实例 = 一个机器人 = 一套 appid），
它们各自连着自己的通道会话（QQ 群 / 用户 openid）。这带来一组只在多实例下才暴露的问题：
**外部平台按机器人隔离的标识，在平台侧被当成了一份。**

本文记的是这一层的模型、不变量与修法；具体代码在 `backend/plugins/qq-channel/plugin.py`，
数据在 `message_channel_refs`（迁移 `0099`）。

## 1. 外部标识是按实例隔离的

同一个 QQ 群、同一条 QQ 消息，在每台机器人那里拿到的都是**各自一套**：

| 标识 | 含义 | 在多台机器人之间 |
|------|------|------------------|
| `group_openid` | 会话（群/用户） | 不同（腾讯按 appid 隔离） |
| `msg_id` | 那条消息的 id（被动回复、撤回） | 不同 |
| REFIDX（`msg_idx` / `ext_info.ref_idx`） | 引用索引（`message_reference`） | 不同 |

拿 A 机器人的 REFIDX 去 B 的群里引用，腾讯回 `40034138`「引用消息越权」并**整条拒发**；
拿 A 的 msg_id 去撤回，撤的是另一条甚至撤不掉。

## 2. 一条站内消息，每个实例各存一份标识

`message_channel_refs`：

| 列 | 含义 |
|----|------|
| `message_id` | 站内消息（`messages.id`） |
| `instance` | 通道实例名（qq-channel 的 `instance`，如 `agent-49`） |
| `conversation` | 该实例看到的会话（群 / 用户 openid） |
| `channel_msg_id` | 本实例这一侧的 msg_id（撤回、被动回复） |
| `channel_ref_idx` | 本实例这一侧的 REFIDX（引用） |

唯一键 `(message_id, instance, conversation)`；写入只有一处 `_record_channel_ref`，
三个时机都走它：新建落库、**认亲合并**（另一台已落库、这一条并过去）、出站回写（AI 自己那条消息的 id）。

`messages.channel_msg_id` / `channel_ref_idx` / `channel_origin` 保留为**兼容字段**：
老数据只有它们，新代码不再以它们为真相。读取规则统一为
**先查本实例本会话那一行，查不到才退回老列（且必须同会话），再不行就不引用/不撤回。**

## 3. 合并同一句话：锁的键必须与实例无关

认亲（`_twin_message` / `_adopt_twin`）是"先查后写"，几台机器人并发送入时看不到彼此未提交的行，
所以要有事务级咨询锁把同一句话排队。锁的键是 **`(通道, 落点群, 摘掉令牌后的正文)`**：

- 不能用 QQ 群 openid —— 那正是每台各不相同的那个值，等于每台各锁各的，排队完全不生效；
- 落点群是平台侧概念，几台机器人对"这句话该进哪个 Copree 群"的判断一致（映射表 + 默认落点）。

同一条落三遍（2026-10-31 真机）就是锁键用了 openid 的后果。

## 4. @ 提及：能用事实的地方不要用名字

平台内统一 `<@!users.id>`（见 [@ 提及统一用 id](mention_ids.md)）。在 QQ 全量事件里：

1. `is_you: true` → **这就是我**。直接补 `mention_token(self._target_user_id)`，不看名字、
   不看别台怎么渲染；
2. `bot: true, is_you: false` → 另一台机器人。按 **agent 名**认（QQ 里显示的机器人昵称就是
   agent 名，是我们配置下去的事实），认得出就补它的真账号；
3. 认不出（第三方机器人、真实 QQ 小号接进来的机器人）→ 照外部人建锚点账号，不否决。

**合并时要保住"点到了谁"**：另一台先落库时，本条事件点到的 AI 令牌要补回合并后那一行，
否则被 @ 的那台看到的是别台渲染的正文，判定成"没点我"（2026-10-31：鲸鱼娘被 @ 后沉默）。

## 5. 影子账号自愈：旧绑定也要收敛

认不出自己人的年代，被 @ 的机器人被当外部人建了锚点，「鲸鱼娘 Deepseek#2」这类影子账号一旦写进
`external_identities`（`(实例, openid) → 影子`），之后 @ 它就一直解析到影子身上。
代码侧现在做两件事：

1. 认回真身的那一刻顺手合并：`_adopt_bot_identity` 调
   `channel_user.merge_channel_accounts(from=影子, to=AI 账号)`，绑定改指本体、它说过的话跟着走、
   空壳删掉。幂等——合并之后条件不再成立；
2. 存量一次性收敛：`data/scripts/heal_channel_identities.py`（默认只报告，`--apply` 执行）。
   判据缺一不可：源账号 `type='external'`、`display_name` 与某个 agent 名一字不差且该 agent 的账号是 AI、
   **这个锚点从没说过话**（messages / dm 无 sender 记录）。宁可漏并，也不并一个同名真人。

## 6. 不变量

- 一条消息在**每个实例**上各有自己的通道标识；任何出站动作只用**发送方自己那一份**。
- 引用/撤回拿不到本实例的那一份就不做——引用是锦上添花，发不出去才是事故。
- 机器人不是"人"：它的身份是 AI 账号（`agents.user_id`），锚点是外部成员的表达方式。
- 合并账号只并在 `external` 源上；真人账号谁是谁只有本人能决定。
