# 进入平台的过场（单一来源）

登录 / 注册成功之后，到主界面真正可用之间，屏幕上播放的那段过场。
实现：`frontend/src/components/EnterTransition.tsx` + `frontend/src/index.css` 的 `.enter-wipe*` 段。
品牌区标记在 `frontend/src/components/LoginBrand.tsx`（登录页与过场共用一份）。

改这里的任何东西之前，先读第 3、4 节——几何和生长方式是这个动效的全部，参数只是修饰。

---

## 1. 它要解决的问题

登录成功后要跳路由、要等主界面首屏数据，中间有一段空窗。如果直接跳，用户会看到闪一下的空白或骨架。
过场的作用是**把这段空窗盖住**，并且让"点按钮"到"进得去"之间是连续的，而不是一次硬切。

用户对这段的口径（按确认顺序）：

- 紫色**从提交按钮的位置**长出来，铺满全屏；
- 铺满之前，按钮那句"验证中"必须一直在、不被盖住；
- 品牌区（logo + 标题 + 副标题）**全程保留**，和文案一起留到最后淡出；
- 文案依次是「验证中」→「验证成功！正在载入……」→「祝您使用愉快！」；
- 主界面加载好了**也不要立刻切**，等这句读完；
- 最后紫色和文字一起淡出。

## 2. 时序

| 时刻 | 画面 |
|---|---|
| 0 | 画布色底幕瞬间不透明（挡住登录页与正在渲染的主界面），紫点在按钮中心 |
| 0 → 420ms | 紫点等比放大到盖住四角（`EXPAND_MS`） |
| 420ms | 加 `.is-on-purple`：暗角、噪点、楔形开始长；文案换成"验证成功！正在载入……" |
| 420 → 1200ms | 进度条从左拉到右（780ms），楔形同时长出 |
| 文案读完 780ms **且** `app-ready` **且** `app-data-ready` | 换成"祝您使用愉快！" |
| 停留 640ms（`WELCOME_HOLD_MS`） | 整层淡出 320ms（`REVEAL_MS`）+ 轻微放大 2% |
| 淡出结束 | 卸载，主界面可见 |

兜底：`app-ready` 最多等 8 秒（`READY_TIMEOUT_MS`），`app-data-ready` 最多等 4 秒（`DATA_GRACE_MS`）。
不是聊天页（比如新用户被送去 `/setup`）时没有首屏数据可等，`Layout` 会直接补发 `app-data-ready`。

## 3. 几何：一点透视

### 灭点

所有楔形的延长线都交于 **Copree 图标中心**：

```
vx = 品牌区实测 left + 品牌区宽 / 2
vy = 品牌区实测 top + 28（半个图标高，图标 56px）
```

用实测坐标而不是写死的百分比：窗口大小、卡片高度、语言换了都会跟着走。

### 左右六块（`faces`）

每块是**建筑立面**：左右两条边**恒竖直**（垂直于地面，不汇聚），上下两条边是"平行线"——
它们的延长线过灭点。所以只给根部两个点（贴屏幕边缘），远端两个点由"过灭点的直线"算：

```
k  = (x1 - vx) / (x0 - vx)
y3 = vy + (y1 - vy) * k
y4 = vy + (y2 - vy) * k
```

**x1 必须停在灭点之前**（左侧块 `x1 < vx`，右侧块 `x1 > vx`）。越过去 `k` 会转负，
形状翻转、溢出一大片，看起来像两块连在一起——竖屏上真实发生过，左第二因此有
`Math.min(0.76 * U, vx * 0.88)` 这层 clamp。

### 底部三块（`floors`）

同一套梯形，**平行边换成水平**：上下两条边水平，两侧边是过灭点的斜线。
底部两点贴屏幕底边，顶部两点由"过灭点的射线"在 `yTop` 处算出：

```
k   = (yTop - vy) / (H - vy)
fx1 = vx + (xa - vx) * k
fx2 = vx + (xb - vx) * k
```

### 响应式

`U = Math.min(W, H)`。

- **横向尺寸**（伸入长度、底部块的宽度）按 `U`：横屏时 `U === H`，与旧参数完全一致；
  竖屏时 `U === W`，自动收进来，不会冲出屏幕。
- **纵向尺寸**（厚度、高度）仍按 `H`——那是竖直方向的量，本来就该跟屏高走。

## 4. 生长方式（以及被否掉的两种）

**现行做法：`clip-path` 四点插值。**

起手是边缘上一条零宽的线，随后两个远端点沿"过灭点"的直线走到终态。
因为两点连线插值仍在连线上，**生长全程透视都是准的**，观感是从边缘长出来。

代价：`clip-path` 是 CPU 属性，780ms 里每帧重绘这几块。桌面上没有感知，
手机（高 DPR）会有轻微掉帧。

**被否掉的两种**（别再试一遍）：

| 方案 | 现象 | 原因 |
|---|---|---|
| `transform: scaleX` 从根部放大 | 像一道门缝向两边张开 | 缩放压缩的是整块图形，根部与远端同时展开 |
| 外层 `overflow:hidden` + 内层平移 | 像平移，不像生长 | 形状整个滑过窗口，读起来是位移不是生长 |

牺牲观感换性能这两条路都走不通。要优化只能动别的地方（比如噪点层的 `mix-blend-mode`）。

## 5. 层序（从下到上）

1. `.enter-wipe-veil` —— 画布色底幕，起手就不透明，负责挡住一切；
2. `.enter-wipe-disc` —— 紫圆，纯色等比放大；
3. `.enter-wipe-tint` —— 暗角，铺满后淡入，中心亮、四周暗；
4. `.enter-wipe-shard` × 9 —— 透视楔形（左右各三 + 底部三）；
5. `.enter-wipe-grain` —— 噪点（`mix-blend-mode: overlay`，把大面积纯色压成有纸感的材质）；
6. `.enter-wipe-brand` —— 品牌区，位置与登录页像素对齐；
7. `.enter-wipe-label` —— 三句文案，锚死在按钮中心；
8. `.enter-wipe-bar` —— 通栏进度条。

品牌区与文案在紫圆**之上**（用户要求"不被挡着"），楔形与暗角在它们**之下**。

## 6. 主题配色

两套配方定义在 `.enter-wipe` 的 CSS 变量上，跟随 `.dark` 自动切换：

| 变量 | 日间 | 夜间 |
|---|---|---|
| `--wipe-bg`（紫幕） | `primary-200` #DDD6FE | `primary-800` #4C1D95 |
| `--wipe-fg`（文字） | `primary-900` #2E1065 | 纯白 |
| `--wipe-vignette`（暗角/楔形） | `primary-600` #6D28D9 | 黑 |

**交接那一帧颜色必须与登录页一致**：起手用 `--tw-text-primary`（跟登录页品牌区同色），
紫圆铺满的瞬间才通过 `.is-on-purple` 换成紫底专用配色。否则登录页那一份消失、
遮罩这一份出现时颜色会跳。

## 7. 事件与状态机

| 事件 | 谁发 | 用途 |
|---|---|---|
| `enter-transition` | `LoginPage`（带上按钮 rect、品牌区 rect、登录/注册 variant） | 起幕 |
| `app-ready` | `Layout`（挂载后双 rAF） | 主界面首帧画好 |
| `app-data-ready` | `ChatArea`（`GET /groups` 的 finally）/ `Layout`（非聊天页） | 首屏数据到位 |

状态机：`idle → expand → loading → welcome → reveal → idle`。
每场过场有一个递增的"代际"编号，旧的定时器链看到代际变了就停手。
`app-ready` / `app-data-ready` 没到时会挂起一个 waiter，到了再继续。

**为什么挂根节点**：跳转一发生登录页就卸载了，跟着它的遮罩会断在半路。
`EnterTransition` 挂在 `main.tsx` 的根节点并 `createPortal` 到 `body`，路由切换只换掉它下面那层。
`dispatchEvent` 与 `navigate` 在同一个 tick，React 一次性提交——所以遮罩首帧和登录页卸载是同一帧，中间没有裸露的一帧。

## 8. 性能与取舍

- 只动 `transform` / `opacity` 的层：底幕、紫圆、暗角、噪点、品牌、文案、进度条——都在合成器上。
- 唯一的热点：九块楔形的 `clip-path` 过渡（每帧重绘）。桌面无感，手机轻微。
- 不碰 `filter: blur` / `box-shadow` 动画（历史上 `backdrop-filter` 卡死过长表单）。
- 整层揭示是"父层一次淡出"，不是逐层降透明度——逐层会让紫圆与暗角互相透出。

## 9. 可访问性

`prefers-reduced-motion: reduce` 下：不做紫圆放大，直接紫幕满屏；所有过渡压到 150ms，
楔形不生长；文案切换保留淡入淡出（它是状态指示，不是装饰）。

## 10. 调参指南

| 想改什么 | 改哪里 |
|---|---|
| 某块的位置 / 长度 / 厚度 | `EnterTransition.tsx` 的 `faces` / `floors` 数组 |
| 明暗浓淡的随机范围 | `onEnter` 里的 `setAlphas`（5%–22%） |
| 各阶段时长 | 文件顶部的 `EXPAND_MS` / `LOADING_MIN_MS` / `WELCOME_HOLD_MS` / `REVEAL_MS` |
| 配色 | `index.css` 的 `.enter-wipe` 变量块 |
| 暗角强度 | `.enter-wipe-tint` 的 `radial-gradient` |
| 噪点强度 | `.enter-wipe.is-on-purple .enter-wipe-grain` 的 `opacity` |

改完跑：`npx tsc --noEmit`、`node scripts/check-ui.mjs`、`node scripts/check-i18n.mjs`。
注意 `--shard-alpha` 是内联设置的，新增块时不要忘了 `alphas` 的长度（现在固定 9）。
