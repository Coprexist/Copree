# 帧的轮生命周期与刺激传导

**状态**：设计稿（未实现）。2026-11-24 由用户提出并逐条修正，助手整理；凡「助手推断」「助手建议」处均非用户构思。
**范围**：状态链（frame stack）、轮的开启/延续/结束、步数额度与借贷、交接（handoff）格式、刺激注入。
**读者**：平台后端维护者、插件作者。

---

## 摘要

平台当前把「一轮」当成一次性的：AI 被唤醒、跑一轮、结束，下一次唤醒从账本重建。
这套模型在云端模型上成立（它们通常一步收尾），但在本地小模型与长任务上暴露三处结构性缺陷：
（i）步数上限约束的是「模型调用次数」，不是「产出量」，模型可以把每一步都用来发消息；
（ii）「AI 正忙时新刺激怎么办」散落在十个入口，仅群聊一处做了注入；
（iii）切帧即等于结束该轮，进度只以「原文尾巴」形式保留，回来时是新一轮而非续跑。

本文给出一个替代模型：**刺激实时传导，额度挂在帧上，回归形态收敛为三种，交接由 AI 填写、系统只做结构补充与过滤。**
§5 与 §6 给出两个命题及其论证；§10 列出失效模式与可观测指标；§11 记录尚未解决的问题。

## 1. 问题与证据

### 1.1 现场数据（2026-11-24，单实例）

| 观测 | 数值 | 来源 |
|---|---|---|
| 一个 turn 内的发送次数 | 22 次 `send_dm`，13:14:16 → 13:26:43 | 后端日志 |
| 该 AI 的步数上限 | `max_tool_rounds=20` + 2 个免费轮 | `agents` 表 |
| 用户中途消息的等待时间 | 13:19:11 发出 → 13:26:43 才进入下一轮，约 7.5 分钟 | 日志 + `dm_messages` |
| 真实提示体积 | 31716 token（其中工具 schema 约 1.75 万） | llama.cpp 日志 |
| 预填充速度 | 37 token/s（负载 14–17，8 核 16 线程） | 实测 |

### 1.2 三个结构性缺陷

- **D1（维度错配）**：`max_tool_rounds` 限制「跑几步」，不限制「说几句」。模型每步发一条，步数耗尽即刷屏。
- **D2（路径分裂）**：群聊在消费端用 `try_claim(ai_id, group_id)` 判定「忙 → 注入当前轮」；私信无此判定，事件干等串行锁。十处生产端各自 `put_nowait`，形状不一。
- **D3（轮不可续）**：切帧走 `pop_state`，当前帧出链；回来时 `build_*_messages` 从账本重建，`_left_conversation` 只带 `doing + tail`。轮的执行状态（工具结果、中间决定）不保留。

## 2. 设计意图（用户原话）

以下为设计者的原始表述，保持原样：

> 「就像神经元一样，刺激肯定是要传导的，然后也应该让 ai 知晓就是实时性的（似乎你不强调他就会默认是实时性的哈），
> 让 ai 自己决定是这一轮结束再过去还是就此终止过去还是保持当前进度把自己弹出，弄完再回来。」

> 「我们实现了一部分，但是没有保持这一轮的进度似乎，直接就结束了。」

> 「有些操作是合法的，但是意义没有合法的，所以我说只有这三种。」

> 「步数预算（上限）就是要挂在每个帧自己身上。」

> 「这个帧弹出（…）的时候自己的剩余预算步数要清空，而不是保持，因为本来这个预算就是为了触到这个情境而提供的，
> 他自己弹出自己的时候就代表着自己的轮（情景）结束了，不然其他帧将他拉起的时候就会是一个不符合不合理的帧数值。」

> 「一个帧找前面的帧借的时候只能借到只剩一个（每个帧如果还要被返回的话帧数至少要有一个），否则就要向前继续借，
> 因为要给那一个帧留下自己弹链总结交接的一步。」

> 「交接不是 ai 自己填的吗」

> 「我们系统结合他自己写的交接和总结，配合结构性补充，去注入给那些中间要 end 的帧并 end 他们。」

> 「那么中间帧就还应该有最后的那一个批量结束自己的帧是谁，以及返回的干了什么，还有回到哪里了
> （他也可以选择直接 end 全部，就没有回到哪里，是说全部结束）。」

> 「有些操作是合法的，但是意义没有合法的。」

由此得到三条设计原则：

- **P1 刺激必达**：外部事件必须实时进入正在执行的轮，不得等待该轮自然结束。
- **P2 选择权在 AI**：去/不去、以何种方式结束，由 AI 声明；系统只执行它声明的动作，不替它决定。
- **P3 进度可续**：切走不等于结束；帧上记录「这一轮是否结束」，回来按其值决定续跑或新开。

## 3. 术语与形式化

### 3.1 记号

| 符号 | 含义 |
|---|---|
| `S` | 状态链，帧的有序序列，末位为活跃帧 |
| `f` | 一帧：`{context_ref, type, doing, why, todo, plan, tail, status, turn_state, steps_used, steps_limit, lent_out, borrow_from}` |
| `ctx(f)` | 帧的作用域键，`group:{id}` / `dm:{sid}` / `world:{id}` / `alarm:{ref}` |
| `steps_left(f)` | `steps_limit(f) − steps_used(f)` |
| `running(S)` | 链上 `turn_state = running` 的帧集合（约定 `|running(S)| ≤ 1`） |
| `A(t)` | 时刻 t 到达的一条刺激，携带 `ctx(A)` 与内容 |
| `step` | **一次模型调用**（LLM round），是额度计量的单位 |
| `message` | **一条发出去的消息**，是产物；一次 step 可以产出 0..n 条 |

### 3.2 帧的轮三态

```
turn_state ∈ { closed, open, running }
```

| 值 | 含义 | 进入条件 |
|---|---|---|
| `closed` | 该帧没有未完成的轮 | 初始；`end_turn` 完成；额度耗尽弹出 |
| `open` | 有未完成的轮，被切走 | 该帧从 `running` 被挂起（suspend） |
| `running` | 正在执行 | `enter(f)` 且该帧 `open` 或新建 |

### 3.3 不变量

设计必须保证以下不变量；实现与测试以此为准：

| 编号 | 不变量 |
|---|---|
| **I1 单活跃（分级）** | **当前并发配置=1**：任意时刻 `\|running(S)\| ≤ 1`。**并发放开后**按作用域计：对任意 `c`，`\|{f : ctx(f)=c ∧ turn_state=running}\| ≤ 1`；全局上限 = 并发配置值。 |
| **I2 借贷不创造** | 在两次额度重置之间，借贷不改变系统内总额度：`Σ steps_left + Σ steps_used + Σ lent_out = Σ steps_limit`。等式只在「新刺激重置」与「弹出回收」时变更。 |
| **I3 保留步** | 对任意被借帧 `f`，`steps_left(f) ≥ 1`；该 1 步不可借，仅可由 `f` 自身消费。 |
| **I4 交接完备** | 任何被 `end` 的帧，都写出一份归属它自己的 `completed_handoff`；不存在「无主结尾」。 |
| **I5 作用域封闭** | 注入到帧 `f` 的内容，只含 `ctx(f)` 所属会话的正文；其它会话仅以结构性事实（类型/数量/时间）出现。 |
| **I6 单向借贷** | 借贷方向唯一：沿链向父帧，不得反向或跨链。 |

### 3.4 链上帧再被拉起的两种语义

> 设计者原话：「链上帧再次被拉起意味着什么，究竟是这一串事情解决完了还是没有解决完是要处理事情，这是两种不一样的。」

| 语义 | 表现 | 系统行为 |
|---|---|---|
| 回来收尾 | 这一串事已办完，回来结算 | 注入「刚完成」+ 交接；是否结束由 AI 决定 |
| 回来继续 | 仍有动作未完成 | 注入未完成事项（未发消息、未完成 todo），由 AI 决定 |

系统**不替 AI 判定**是哪种：两种语义都由注入的事实集区分，选择权在 AI（P2）。
助手曾试图用 `intent_done` 布尔量自动判定，被设计者否定——判据不成立（见 §11.2 第 2 条）。

## 4. 额度模型

### 4.1 归属与重置

额度挂在帧上（用户原话：「步数预算（上限）就是要挂在每个帧自己身上」），但**上限的来源是触发它的刺激**：

- **每一**新刺激 `A` 落在帧 `f`：`f.steps_limit := limit(f)`，`f.steps_used := 0`，`f.turn_state := running`。
  ——设计者原话：「有触发就重制上限」；并明确否定「这算无限续命」的担忧：「不会无限续命，除非外界持续刺激，
  那么确实应该持续处理情景啊」。**额度由外部刺激驱动，不是模型自驱**。
- 主动切换（`leave`/`enter`，无新刺激）：不重置，沿用 `steps_used`。
- 被调度切回（无新刺激）：不重置，沿用 `steps_used`。

> **刺激的界定（关键）**：只有**外部事件**重置额度——人发的消息、通道消息、闹钟到点、世界事件、联邦消息。
> **系统自身的通知不重置**（如 `shout_change` 的 `notice`：能力/记忆变更通知）——否则系统内部一句话就能给 AI 续命，
> 那就真成了「自己刷额度」。

> 这条区分是本模型的防刷核心：**刺激能续额度，切帧不能**。AI 无法靠反复切帧给自己加步数；
> 而只要外部还有人在说话，它就应该继续处理——那是设计期望，不是漏洞。

### 4.2 借贷

**场景**：帧 `f` 的 `steps_left(f) = 0`，但仍需要继续处理。

**关于原话措辞的说明**：设计者原话是「每个帧如果还要被返回的话帧数至少要有一个」；
按上下文（「给那个帧留下自己弹链总结交接的一步」）理解为「**至少保留 1 步**」，即 I3。

**规则（形式化）**：

```
borrow(f):
  for p in parents(f):                  # I6：只向父帧
    if steps_left(p) > 1:               # I3：保留 1 步
      take = min(needed, steps_left(p) - 1)
      p.lent_out += take; p.steps_used += take
      f.borrow_from.append({frame: p.id, n: take})
      return take
  return 0                              # 链底仍不足 → 拒绝，并告知 AI
```

**记账**：借入方记 `borrow_from`，出借方记 `lent_out`；出借方帧结束后账目不删（否则无法审计）。

### 4.3 回收

帧弹出（`end_turn` 或额度耗尽）时，`steps_left(f) := 0`（用户原话：「剩余预算步数要清空」）。
这是**显式回收**，不是守恒破坏：I2 的等式在回收时右侧同步减少。

### 4.4 命题 1（额度不创造）

**命题**：AI 无法在**没有外部新刺激**的情况下延长自己的处理（额度不因切帧、借贷或反复切换而增长）。

**论证**：

1. 每次模型调用只从「当前 `running` 帧及其祖先的 `steps_left`」中扣减（§4.1、§4.2）。
2. 借贷仅转移，不新增（I2），且受 I3 约束。
3. 额度重置的唯一触发条件是「新刺激落在该帧」（§4.1）；`leave`/`enter` 不产生刺激。
4. 因此若外部无新刺激，总调用次数 ≤ `Σ steps_limit(f)`；一旦新刺激到达，额度重置——**这是期望行为**，
   因为持续的外界刺激意味着情景仍在持续，AI 应持续处理。

**推论（防刷）**：模型不能靠自己「切来切去」获得新的步数；它只能等待外界再说话。
**边界（成本）**：外部刺激可以是高频的，因此部署方仍需小时/天总量闸（§10 F1、§11.2 第 4 条）——
那不是防止 AI 作弊，是防止**外部刺激成本失控**。

## 5. 回归形态

### 5.1 原子操作

```
leave(current, 方式)   方式 ∈ { suspend, end }
enter(target)          将 target 置为 running（从链中拉起，不压新帧）
```

### 5.2 穷举

回归 = `leave(方式) × 中间帧(keep|end) × enter(目标)`，共 6 种组合。

### 5.3 命题 2（合法形态恰为三种）

**命题**：在 I1（单活跃）与「帧是栈、末位活跃」的前提下，操作合法且语义合法的回归形态恰有三种。

**论证（逐条排除）**：

| 组合 | 冲突的不变量/语义 | 结论 |
|---|---|---|
| suspend + keep + enter | — | 合法（形态 1） |
| end + keep + enter | — | 合法（形态 2） |
| end + end + enter | — | 合法（形态 3） |
| suspend + end + enter | 中间帧被销毁而自身仍留在链上，回来后自身即成为「中间」，与「中间帧表示过渡」矛盾 | 排除 |
| end(目标帧) + enter(同一目标帧) | 同一帧同时 `ended` 与 `running`，违反 I1 | 排除 |
| 无 leave + enter | 链上出现两个 `running`（I1） | 排除 |

**反例说明**：第四种在数据结构上可执行（先删中间帧、再切活跃指针），因此不是「非法操作」，而是**语义非法**——
执行后链的形态无法对应任何现实情景。这正是设计者所说「有些操作是合法的，但是意义没有合法的」。

**推论**：其余组合不应暴露给调用方；实现层应对 `leave/enter` 的参数组合做白名单校验。

### 5.4 三种合法形态的语义

| # | 形态 | 链上结果 | 当前帧额度 | 中间帧额度 | 语义 |
|---|---|---|---|---|---|
| 1 | suspend + enter | 当前帧挂起保留 | 保留* | 不动 | 走开一会儿，回来继续 |
| 2 | end + enter | 当前帧出链 | **清零** | 不动 | 这帧演完了，退场 |
| 3 | end + end + enter | 整段出链 | **清零** | **清零** | 这一整段收尾 |

> \* 形态 1 的「保留」只适用于**无新刺激的切回**；若该帧是被新刺激 `enter` 的，按 §4.1 重置额度。

> 设计者原话：「他自己弹出自己的时候就代表着自己的轮（情景）结束了。」

### 5.5 全部结束之后

> 设计者原话：「下一个刺激来的时候拿个刺激对应的帧不是就回加入链中吗」

是。`ensure_active_frame` 的语义是「链上有该 `context_ref` 的帧就拉起，没有就新建」，
「链为空」与「链上没有该会话的帧」走**同一条路径**，因此不需要任何特殊分支。

## 6. 交接（handoff）

### 6.1 归属：内容由 AI 写，结构由系统给

交接的内容（`doing` / `why` / `todo` / `tail`）来自 AI 的工具调用参数，系统不生成内容。
系统只提供结构词与拼接：`📝 刚完成`、`← 从…来`、`回到…`、`整段结束`。

### 6.2 单帧格式（现状）

被 end 的帧把 `completed_handoff` 写到**回去的那一帧**上：

```python
completed_handoff = {
    "type": prev.type, "doing": (prev.doing or prev.why)[:200],
    "label": prev.label, "tail": prev.tail,
}
```

渲染：

```
📝 刚完成: [dm] 把名单理完了
   ← 从[dm] 在跟阿岚核对名单来 · 原因: 阿岚问要人 · 回去继续: 把结果发群里
```

### 6.3 批量格式（扩展）

中间帧的交接在单帧格式上追加结构三件：**谁收的尾、收尾者干了什么、回到哪里**。

```python
completed_handoff = {
    …, 
    "batch": {
        "size": 4, "index": 2,
        "closer": {"type": "group_chat", "label": "群 A", "doing": "把名单发到了群里"},
        "target": {"type": "group_chat", "label": "群 A"},   # None = 全部结束
    },
}
```

```
📝 这一段结束: [dm] 你在核对名单
   ├ 你是这一段里的第 2 层（共 4 帧）
   ├ 收尾的是: [group_chat] 群 A「赛博少宇」（把名单发到了群里）
   └ 回到: [group_chat] 群 A
```

`target = None` 时末行改为「整段结束，没有回到任何帧」。`size` / `index` 为助手建议字段。

### 6.4 命题 3（交接完备性）

**命题**：形态 3（批量 end）若按 §6.3 逐帧注入后 end，则对任意被 end 的帧 `f`，存在且仅存在一份 `completed_handoff` 归属 `f`。

**论证**：

1. 逐帧处理：每个 `f` 在出链前接收一次注入（I4）。
2. 注入失败即停（§6.5），后续帧保持 `open`/`running`，不产生无主结尾。
3. 目标帧只接收「这一段结束」的汇总，不再接收中间帧的逐条内容——避免同一事实重复注入。

**反例**：若一次性把所有中间帧出链后才统一写交接，任一帧写入失败都会留下无主结尾；且失败后无法定位是哪一个帧。

**收尾者自身的交接**：发起批量 end 的帧（`closer` 自己）同样被 end，它走**单帧交接**（§6.2）——内容就是它自己填的 `doing`；
它不接收 `batch` 块（`batch` 是给中间帧描述「这一段的全貌」用的，收尾者本来就掌握全貌）。

### 6.5 顺序与失败处理

- 顺序：从当前帧沿链向父帧逐帧处理（`current → … → target` 的前一帧）。
- 失败：注入或落库失败即停止，已处理帧保持 end，未处理帧保持原状态，返回失败点。
- 幂等：同一 `(frame_id, closer_id)` 重复执行不产生第二份交接。

## 7. 刺激传导

### 7.1 注入协议

注入分三段：**刺激本身 / 当前状态 / 切走的后果**。必须带时间与来源——设计者指出「不强调他就会默认是实时性的」。

```
〔实时刺激〕私信 · 阿岚（dm:1_163），22:41
「你今晚回来吃饭吗？」

〔你现在的状态〕
- 在：群 A（group:12），本轮第 5/20 步
- 本轮尚未发出消息
- 切走：本帧记为 open，可回来继续；额度保留
```

条件建议（避免常驻说教导致模型拘谨）：

| 上一动作 | 附注 |
|---|---|
| 写文件 / 发消息进行中 | 「先做完再切」 |
| 检索 / 思考 | 不附注 |

### 7.2 命题 4（跨作用域不串台）

**命题**：若注入遵守 I5，则 AI 不可能把 `ctx(f)` 之外的正文当作 `f` 所在会话的发言依据。

**论证**：注入块显式声明 `ctx` 与当前作用域；内容只含本会话正文；其它会话仅以元信息出现。
但需注意：这是**接口层**保证，模型仍可能自行臆测——这属于模型能力问题，不是协议漏洞（见 §10 F3）。

## 8. 职责边界

| 事项 | 责任方 |
|---|---|
| 刺激的到达、注入时机、作用域过滤 | 系统 |

## 10. 失效模式与可观测指标

| 编号 | 失效模式 | 触发条件 | 可观测指标 |
|---|---|---|---|
| F1 | 刺激风暴（期望行为，但需成本闸） | 外部高频刺激持续重置额度 | 同一帧单位时间内 `steps_limit` 重置次数；AI 小时/天调用次数 |
| F2 | 借空父帧 | 未执行 I3 | 出现 `steps_left = 0` 且 `turn_state = open` 的帧 |
| F3 | 串台 | 注入未做作用域过滤 | AI 在会话 A 提到会话 B 的正文 |
| F4 | 帧抖动 | AI 频繁主动切帧 | 单位时间 `leave/enter` 次数 |
| F5 | 无主结尾 | 批量 end 未逐帧注入 | `ended` 帧缺 `completed_handoff` 的比例 |
| F6 | 交接失真 | AI 填写的 `doing` 与实际动作不符 | 交接文本与工具日志的抽样比对 |

## 11. 未解决问题（作者注）

设计者明确表示：「我说的这个仍然有逻辑漏洞，你可以注一个作者自己说这里还要继续优化如果你决定采纳的话，或者你自己想想漏洞是什么。」

### 11.1 已决定延期（不是未决）

**发言条数上限**：

- 问题：`step`（额度计量单位）与 `message`（产物）是两个维度。一次 step 可以产出多条消息，
  所以把「步数」当「发言上限」是维度错配——2026-11-24 的 22 条刷屏正是这么发生的。
- 现状：**先不加硬约束**。设计者判断：「一步确实可以说多句话，这个上限先留着，之后设置吧」——
  即未来做成**可配置项**（与 `max_tool_rounds` 同级，可按档位预设、可单独覆盖），而不是写死常量。
- 在此之前：额度重置会让「外部持续刺激 → AI 持续发言」，这是**已知且接受**的行为。

### 11.2 未解决


1. **「这一段」的边界**：按栈区间还是按情景？栈区间会误伤夹在中间的其它会话帧。
2. **「是否真的做完」的判定**：目前只能靠 AI 自述 + 客观信号交叉；弱模型会撒谎。
3. **被借帧的感知**：父帧回来时额度已变少，是否要告知「这些步不是我花的」。
4. **全局总闸**：额度可被外部刺激反复重置，因此总调用量由「刺激频率 × 每轮上限」决定；部署方需要小时/天总量闸兜底（不是防 AI 作弊，是防成本失控）。
5. **超时**：额度已由刺激驱动，超时不再影响额度；但它影响**交接时效**——隔数小时回来的帧，其 `tail` 与 `doing` 是否还有意义，需要在注入时降权或标注「这是 X 小时前的进度」。
6. **汇报的过滤**：回 A 汇报时，别处会话的细节不应进入 A 的作用域。
7. **切帧的身份重入**：同一帧被反复 `enter` 时，`turn_state` 与 `steps_used` 的一致性需幂等保证。
