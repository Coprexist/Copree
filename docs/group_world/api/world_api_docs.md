## AI 接入方式

1. 世界 AI 工具列表含 **`view_api_doc(section)`**（分区号 `01`~`10`），工具描述即上表（区名 + 区介绍）。
2. **先看区介绍再开区**，按需打开，不要一次全读。
3. 常用对应：建网页→03（必要时 06）；套 UI→04；群里说话→05；取通知→07；报错→08；写世界代码/受控接口→09；同步/限流异常→10。

## 快速上手（给 agent 的 6 步）

1. 了解身份与注入变量 → **01**
2. 写世界主页 → **03**（`file_write` 自动建目录）
3. 套现成 UI → **04**（list → view → apply）
4. 群里发言 → **05**（`send_group_message`，默认发到绑定群）
5. 用户改了代码 → **07**（对话开始先取通知）
6. 报错 → **08**
7. 同步报「无变化」或触发 429 → **10**

## 界面硬性要求（每次创建/修改页面都必须遵守）

1. **必须适应手机（竖屏横屏都能玩；不锁定方向，也不要求单独做横屏版）**：竖屏 320px 窄屏下不溢出、可操作、可读（font-size 不小于 12px，可点击目标不小于 44px）；横过来是矮视口（约 844×390），布局要跟着变——用 `@media (orientation: landscape)` 与 `max-height` 调布局（顶部信息收紧、按钮横排、画布按短边缩放），底部操作区/输入框/关键按钮必须始终在可视区内（页面设了 viewport-fit=cover 的，横屏用 env(safe-area-inset-left/right) 避开刘海）；高度用 `100dvh`（不要 `100vh`：手机浏览器地址栏会吃掉底部，横竖屏都会）。
2. **必须直接前端化整个界面，操作和视图渲染都要前端化**：
   - 视图渲染前端化：界面就是 HTML/CSS/JS 前端页面本身，页面 DOM 由前端 JS 渲染，不依赖后端渲染模板；
   - 操作前端化：页面操作（点击/输入/状态切换/局部更新）在前端直接完成，能前端处理就不走后端；需要后端数据/持久化时才调接口（相对路径 fetch 或受控数据 API，06 分区）。
3. **操作绝不借道群聊**：页面上的每个按钮/入口都要有直接的点击反馈（前端直接执行或调事件通道），**禁止写「从群聊进入/群内直接发指令：探索 战斗 商店…」这类引导文案**，禁止让用户离开页面去群里发指令才能操作；页面操作一律走事件通道（06 分区 4.1，`POST /world/{id}/api/event`），世界程序回复用 SSE 状态（`publish`）。只有真正关键、需要别人在群里看到的事件（如宣布重大结果、求助他人）才用群消息 API。
4. **全屏**：平台支持全屏——沉浸页顶栏有全屏按钮；页面自己也可以加一个：按钮里调 `document.documentElement.requestFullscreen()`（平台 iframe 已授权 `fullscreen`）。棋盘/卡牌/地图/游戏这类沉浸内容建议提供全屏按钮，配合横屏体验最好。
