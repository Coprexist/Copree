# Copree 安全与权限模型 / Security & Permission Model

> **适用读者**：管理员 / 部署者 / 二次开发者
> **相关文档**：[管理与开发者手册](./管理与开发者手册.md)、[测试策略](./test_strategy.md)、[部署合规建议书](../deployment-compliance.md)
> **版本**：v1.0 | **更新**：2026-09-13

本文说明 Copree 里「谁能看什么、谁能改什么」是怎么判定的，以及部署到公网前必须做的加固。
背景是一轮**无凭据 / 任意注册用户**视角的公网自测（报告本地留存，未入库）：12 项里仓库内可修的
已全部整改，剩下的取舍也在这里写明理由，避免下次又被当成新漏洞重复排查。

---

## 一、三条铁律

权限判定必须只有一个入口。凡是"每个路由自己写一遍"的地方，迟早会漏一个——本轮公网自测
暴露出来的三个问题（`/admin/tools/backpack` 漏挂管理员鉴权、WS 群订阅没有成员校验、
`/fs/public` 把文件权限校验整段丢掉）就是同一个病的三种形态。

| # | 判定对象 | 唯一入口 | 位置 | 典型反例 |
|---|---------|---------|------|---------|
| 1 | 群相关访问（消息 / 详情 / 成员） | `require_group_member` 依赖 | `app/routers/deps.py` | 只判"已登录"就放行 → 任意账号读任意群历史 |
| 2 | 管理员角色 | `load_user_role()`（回查 DB） | `app/utils/auth.py` | 信 JWT 里的 `role` → 降权后旧 token 7 天内仍是管理员 |
| 3 | 匿名可下载的文件 | `MaintenanceManager.is_public_file()` | `app/services/infrastructure/maintenance.py` | 丢掉权限校验的"公开下载"普通接口 → 自增 ID 枚举拖全站文件 |
| 4 | 出站请求的目标地址（SSRF） | `classify_address()` 判地址 + `safe_get()` 取数 | `app/utils/pure/url_guard.py` / `app/tools/file_operations/web_fetch.py` | 只看第一次 DNS 解析、或拿 `is_private` 当"内网"的全部答案 → 误拦与漏拦同时发生 |

补充约定：

- **群消息的写路径**由 `app/chat/gm.py:send_gm_message` 校验（`allow_non_member=False`），
  与读路径共用同一个 `is_group_member` 判定，不存在两份口径。
- **WS 与 REST 同口径**：`WS /ws` 订阅群时也走 `is_group_member`，否则实时通道会绕过读接口。
- **群审批权＝可见性**（2026-09-21）：入群申请与待审邀请既不在群成员接口里，也不在群详情的
  返回字段里，只出现在 `/requests/pending`，且**只对该群群主/管理员可见**；审批动作在
  `app/chat/gm.py::require_group_approver` 一处校验（`APPROVER_ROLES` 是唯一角色口径）。
  别在端点里另写一遍角色判断——那样迟早出现"能看见但批不了"或反过来的组合。
- **匿名下载白名单的边界**：只有被维护弹窗引用的图片 `/fs/public/{file_id}` 允许匿名取
  （硬维护时用户必然未登录，`<img>` 也带不了 Authorization）。需要新增匿名可访问的资源时，
  请显式扩这个白名单，**不要**恢复成"通用文件表随便下"。
- **出站请求（SSRF）的口径**："哪些地址算内网"只在 `app/utils/pure/url_guard.py::classify_address`
  定义一处，联网取数只在 `safe_get()` 一处（自己挑地址、把选中的 IP 钉进连接、Host/SNI 用原域名、
  **每一跳重定向都复检**）。两条硬要求：① 别拿 `is_private` 当全部答案——IPv6 的 `is_private` 把
  `2001::/23` 整段算进去，Teredo 这类"本机拨不到"的地址会被误报成"内网地址"，还会把同域名下那个
  能用的公网 IPv4 一起毙掉（2026-09-16 实测）；② 别只查第一步就让 `httpx` 自己重解析再拨，
  那等于把判定结果丢掉（DNS rebinding 与重定向都能绕过去）。
- **镜像轮播的约束**（`mirror_table.py` + `safe_get`，2026-09-16 加）：只有**官方失败**才轮到镜像，
  **只读 GET**、不带任何凭据；镜像自己也要过同一套 SSRF 复检；用了镜像必须标出来（结果里的 `via`），
  因为内容来自第三方——不能让 AI 或用户以为那还是官方原文。表里只登记**实测过的**镜像。

## 二、受保护入口速查

| 路径 | 方法 | 要求 | 说明 |
|------|------|------|------|
| `/gm/{group_id}/messages` | GET | 群成员 | `require_group_member` |
| `/gm/{group_id}/messages` | POST | 群成员 | `send_gm_message` 内部校验，非成员拒绝 |
| `/groups/{group_id}` | GET | 群成员 | 群详情 |
| `/groups/{group_id}/members` | GET | 群成员 | 成员列表（@提及用） |
| `/requests/pending` | GET | 登录 | 红点与「申请列表」同一口径；入群/邀请项只含我有审批权的群 |
| `/groups/join-requests/{id}/approve\|reject` | POST | 该群群主/管理员 | 审批入群申请，通过才入群 |
| `/group-invitations/{id}/approve\|deny` | POST | 该群群主/管理员 | 批准后才通知被邀请人；被邀请人自己的 `accept`/`reject` 是另一套 |
| `WS /ws` `subscribe {group_id}` | — | 群成员 | 与 REST 同口径 |
| `/chat/user/{user_id}` | GET | 登录 | 仅展示字段（昵称 / 头像 / 语言） |
| `/chat/user/{user_id}/friends` | GET | 登录 + 本人 | 他人一律 403 |
| `/admin/**` | 全部 | 管理员（DB 复核） | 静态守卫保证不漏挂 |
| `/fs/download/{file_id}` | GET | `check_file_access` | 原有的权限校验路径 |
| `/fs/public/{file_id}` | GET | 维护图片白名单 | 不在白名单一律 403 |
| `/fs/download-avatar/{filename}` | GET | 公开 | 仅 avatars 目录，无元数据 |
| `/world/{id}/files/*` | GET | 公开 | 世界页面 = 可分享链接，见第五节 |
| `/openapi.json`、`/docs` | GET | 非生产环境 | 生产环境 404 |

## 三、生产环境加固清单

### 3.1 打开生产开关：`ENVIRONMENT=production`

它影响两件事：接口文档是否暴露、以及启动时是否强制要求独立的加密密钥。

⚠️ **顺序很重要**：设为 production 后，若 `ENCRYPTION_KEY` 未设置或等于 `JWT_SECRET_KEY`，
应用会**拒绝启动**。而随手换一个新值，已加密的 API Key 会全部解不开。所以先读出当前密钥：

```bash
# 读出当前持久化的加密密钥（开发态自动生成，位于数据目录）
docker exec ai_group_backend cat /app/data/encryption_key
```

把它的值写进 `.env` 的 `ENCRYPTION_KEY`，再设 `ENVIRONMENT=production`，最后重启后端：

```bash
# 改完 .env 后重启后端容器
docker restart ai_group_backend
# 确认起来了（就绪日志与健康检查）
curl -sf http://127.0.0.1:5228/health && echo OK
```

### 3.2 接口文档自动关闭

生产环境下 `openapi_url=None`，自定义 `/docs` 与 `/docs/zh` 直接 404（共 319 个接口的
全量清单不该出现在公网）。开发环境照旧可用，不需要额外开关。

### 3.3 安全响应头

| 响应头 | 是否加 | 说明 |
|--------|--------|------|
| `X-Content-Type-Options: nosniff` | ✅ | 禁止浏览器按内容嗅探类型执行上传文件 |
| `Referrer-Policy: no-referrer` | ✅ | 外链不携带来源路径 |
| `X-Frame-Options` / `frame-ancestors` | ❌ 刻意不加 | 世界页面需要被其它实例 / 宿主 iframe 嵌入 |
| `Content-Security-Policy` | ❌ 刻意不加 | 世界 HTML 依赖内联脚本，要上 CSP 得先做 nonce 体系 |
| `Strict-Transport-Security` | ❌ 不在应用层加 | 后端只见 http（TLS 在反代/frp 终结），应在那一层加 |

### 3.4 联邦出站 TLS

联邦对端之间的出站 HTTP（头像同步等）统一走 `peer_http_client()`，**默认校验证书**。
对端使用自签证书时，指定 CA 而不是关校验：

| 变量 | 默认 | 说明 |
|------|------|------|
| `FEDERATION_TLS_VERIFY` | `true` | 是否校验证书（保持 true；除非你明确知道对端无法提供证书） |
| `FEDERATION_CA_BUNDLE` | 空 | 自签对端的 CA bundle 路径；设置后优先于上面的开关 |

### 3.5 反代层（应用之外）

- HSTS、真实客户端 IP 还原、限速与 IP 白名单都在 TLS 终结层做；
  docker 端口映射下后端看到的源永远是网关地址，应用层猜不出来（详见[管理与开发者手册](./管理与开发者手册.md)）。
- frp 控制端 token 用 ≥32 字符随机值，SSH 隧道不要直接暴露公网。

## 四、自查命令（可整段复制）

准备两个账号的 token：一个是目标群成员（下面记作 `T_MEMBER`），一个不属于该群（`T_OUTSIDER`）。
可以直接用登录接口取：

```bash
B=http://127.0.0.1:5228
T_MEMBER=$(curl -s -X POST $B/auth/login -H 'Content-Type: application/json' \
  -d '{"login_id":"<成员账号>","password":"<口令>","method":"direct"}' | python3 -c 'import json,sys;print(json.load(sys.stdin)["access_token"])')
T_OUTSIDER=$(curl -s -X POST $B/auth/login -H 'Content-Type: application/json' \
  -d '{"login_id":"<非成员账号>","password":"<口令>","method":"direct"}' | python3 -c 'import json,sys;print(json.load(sys.stdin)["access_token"])')
```

然后逐条对照（期望值写在注释里）：

```bash
B=http://127.0.0.1:5228
GID=1
code() { curl -s -o /dev/null -w '%{http_code}' "$@"; }

# 越权读群：非成员必须 403，成员必须 200
echo "outsider gm      $(code -H "Authorization: Bearer $T_OUTSIDER" $B/gm/$GID/messages)"      # 403
echo "member   gm      $(code -H "Authorization: Bearer $T_MEMBER"   $B/gm/$GID/messages)"      # 200
echo "outsider group   $(code -H "Authorization: Bearer $T_OUTSIDER" $B/groups/$GID)"            # 403
echo "outsider members $(code -H "Authorization: Bearer $T_OUTSIDER" $B/groups/$GID/members)"    # 403

# 私信：人→人、AI→人一律要求互为好友（AI 被拒时提示先发好友申请）；找 AI（人→AI）与 AI↔AI 放行；
#       系统通知与"已有会话里的回复"不拦（外部通道的被动回复走这条）
# 用户信息与好友：匿名 401，他人好友列表 403
echo "anon     user    $(code $B/chat/user/1)"                                                    # 401
echo "outsider friends $(code -H "Authorization: Bearer $T_OUTSIDER" $B/chat/user/1/friends)"    # 403 unless T_OUTSIDER is user 1

# 管理端点：匿名 401，普通用户 403，管理员 200
echo "anon     backpack $(code $B/admin/tools/backpack)"                                          # 401
echo "outsider backpack $(code -H "Authorization: Bearer $T_OUTSIDER" $B/admin/tools/backpack)"  # 403

# 匿名文件下载：白名单外一律 403（原理见第一节第 3 条）
echo "anon     public/6 $(code $B/fs/public/6)"                                                   # 403

# 安全头
curl -sI $B/health | grep -iE 'x-content-type-options|referrer-policy'
```

**白名单的正向自查**（确认维护弹窗图片仍然能匿名显示）：把某张图片的 URL 加进维护图片列表，
匿名取一次应为 200；移出后应为 403。

```bash
B=http://127.0.0.1:5228
# 加白名单（把 6 换成你的维护图片 file_id）
docker exec -w /app ai_group_backend python -c "import json; json.dump(['/fs/public/6'], open('/app/data/maintenance_images.json','w'))"
curl -s -o /dev/null -w 'in-whitelist %{http_code}\n' $B/fs/public/6     # 200
# 移除白名单
docker exec ai_group_backend rm -f /app/data/maintenance_images.json
curl -s -o /dev/null -w 'removed     %{http_code}\n' $B/fs/public/6     # 403
```

**WS 群订阅自查**（非成员订阅必须被拒）：

```bash
docker exec -i -e TOK="$T_OUTSIDER" -w /app ai_group_backend python - <<'PY'
import asyncio, json, os, websockets
async def main():
    async with websockets.connect("ws://127.0.0.1:8000/ws?token=" + os.environ["TOK"]) as ws:
        await ws.send(json.dumps({"type": "subscribe", "group_id": 1}))
        print(await asyncio.wait_for(ws.recv(), timeout=6))   # 期望 error：你不是该群成员
asyncio.run(main())
PY
```

## 五、明确保留的设计取舍

这些是**已知且有意保留**的，不是漏改；改之前先确认产品语义。

| 项 | 现状 | 为什么保留 | 什么时候该改 |
|----|------|-----------|-------------|
| 生产用 Vite dev server | `docker-compose.yml` 里前端跑 `yarn dev`，且经 frp 对外 | 开发期热更新方便；改静态托管是部署决策 | 正式对外运营前，改为 `vite build` + 静态托管，dev server 只绑 127.0.0.1 |
| 世界页面匿名可读 | `/world/{id}/files/*`、`/preview` 无需登录 | 世界页面设计上就是可分享链接（iframe 带不了 token），数据库里也没有"草稿"字段 | 产品要"未发布世界不可见"时，先给 `worlds` 加可见性字段 + 迁移 |
| 无 `X-Frame-Options` / CSP | 见 3.3 | 世界页面要能被嵌入；世界 HTML 依赖内联脚本 | 世界代码全面改为外链脚本 + nonce 之后 |
| frpc / SSH | 基础设施侧配置 | 不在仓库范围 | 随时：换强 token、SSH 不直接暴露 |
| 文件 ID 是自增整数 | `file_metadata.id` | 改 UUID 影响面大（前端、世界代码、接口契约） | 匿名下载已白名单化，收益有限；真有需要再单独立项 |

## 六、自动化守卫

「漏挂权限」不靠人肉 review，靠会红的用例：

```bash
# 在后端容器内跑（TEST_DATABASE_URL 必须指向测试库）
PROD=$(docker exec ai_group_backend printenv DATABASE_URL)
TEST=$(printf '%s' "$PROD" | sed 's|/ai_group_chat|/ai_group_chat_test|')
docker exec -w /app \
  -e TEST_DATABASE_URL="$TEST" \
  -e TEST_DATABASE_URL_SYNC="$(printf '%s' "$TEST" | sed 's|+asyncpg||')" \
  ai_group_backend python tests/run_without_pytest.py test_security_guards
```

守卫清单（`backend/tests/test_security_guards.py`）：

| 用例 | 锁住什么 |
|------|---------|
| `test_admin_routes_all_require_admin` | `/admin` 下任何路由缺 `require_admin` 即失败（含新增路由） |
| `test_group_read_routes_require_membership` | 群消息 / 群详情 / 群成员必须挂 `require_group_member` |
| `test_ws_group_subscribe_checks_membership` | WS 群订阅必须有成员校验 |
| `test_chat_user_routes_require_login` | `/chat/user/*` 必须要求登录 |
| `test_agent_access_rechecks_role_from_db` | 角色判定必须回查 DB，不得信 JWT |
| `test_public_file_route_checks_maintenance_whitelist` | `/fs/public` 必须走白名单 |
| `test_public_file_id_parsing`、`test_whitelist_denies_by_default_and_allows_listed_files` | 白名单解析与"默认拒绝"语义 |
| `test_docs_closed_in_production` | 生产环境 `/docs` 必须 404 |
| `test_federation_outbound_tls_verification_enabled` | 联邦出站不得再现 `verify=False` |

**两条真实教训**（这也是为什么白名单必须有正向用例）：

1. 白名单第一版把正则里的数字类字符写坏了，导致**白名单内的图片也被 403**——只测"该拒的拒了"
   不会发现，必须同时测"该放的放了"。
2. 加守卫的当天，它立刻抓出两条**内联手写管理员校验**的 admin 路由：
   `POST /admin/cleanup/files` 与 `GET /admin/cleanup/stats`——功能上没漏（各自查库比对了角色），
   但正是"逐个手写"的典型：判定逻辑抄了两份，将来改口径必漏其一。现已折进 `require_admin`。

## English Summary

Copree 的权限判定只有三个入口，其余地方一律引用它们：

- **Group access** — `require_group_member` (backed by `chat/gm.py:is_group_member`);
  the same check guards WebSocket group subscriptions, so the realtime channel cannot bypass REST.
- **Admin role** — `load_user_role()` reads the role **from the database**. Never trust the
  `role` claim inside a JWT: a demoted admin keeps a valid token for up to 7 days.
- **Anonymous file download** — only files referenced by the maintenance popup
  (`MaintenanceManager.is_public_file()`) may be fetched without a token. Everything else
  returns 403. Need another anonymous resource? Extend this whitelist explicitly.

Hardening checklist before exposing to the internet: set `ENVIRONMENT=production`
(and `ENCRYPTION_KEY` **first**, copied from `/app/data/encryption_key`, otherwise the app
refuses to start or encrypted API keys become unreadable); API docs are then disabled
automatically; keep `FEDERATION_TLS_VERIFY=true` and use `FEDERATION_CA_BUNDLE` for
self-signed peers; add HSTS at the TLS-terminating reverse proxy, not in the app.

Repo hygiene: this repository is public. Audit reports, credentials, production domains /
entry IPs and tunnel port maps never enter git — they live in the untracked
`gitignore-本地docs/` at the repo root (reports go in its `security/`), backed by
`SECURITY-AUDIT-*.md` / `PENTEST-*.md` safety nets in `.gitignore`. Share conclusions,
not raw reports: sanitize them into `docs/`. See [SUMMARY](../SUMMARY.md) ·
本地私有资料 (Local-only material).

Regression guards live in `backend/tests/test_security_guards.py` — missing an auth
dependency on any route fails the suite instead of waiting for the next penetration test.
