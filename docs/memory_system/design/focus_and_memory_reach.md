# 焦段与记忆适用范围

> **版本**：v1.1（草案）
> **日期**：2026-09-26
> **状态**：待评审，尚未落地
> **文档规范**：设计类文档统一结构，语言规范，命名规范

---

## 一、问题

跨会话传递内容有两条路：

| 路线 | 做法 | 局限 |
|------|------|------|
| 一 | 把上一状态的内容交回它再回复一次，或把别的会话原文注入当前会话 | 点对点，成本随状态数上升，更早的状态覆盖不到；原文注入已在 v0.2.1 因跨群"历史重播"废止（`_build_cross_conversation_context` 恒返回空表） |
| 二 | 本轮发生的事写成记忆，由记忆的适用范围决定它在哪里能被想起 | 多对多、可累积 |

本设计取路线二。与之一路的三件现役构件各管一段，均不改动：

- 状态帧交接 `handoff.tail`：管"刚才说到哪"，最多 4 轮原文，一次性注入；
- `cross_state_note`：管临时约定，40 次 API 调用内投递，投给别的会话后过户固化；
- 记忆：管长期事实，可检索。

缺的是记忆的**适用范围**。现有 `scope`（`private` / `group` / `cross_user`）表达的是"谁能看见"，不是"该在哪一层被想起"：一道题在某个群讲过，锚 `group` 就锁死在那一个群，锚 `private` 则处处可见，中间那一层没有落点。

同时缺**权值**：两套记忆都没有"该活多久"的表达，衰减逻辑要么不存在，要么写在无调用者的死代码里（见第十一节）。

## 二、命名

| 概念 | 中文 | 代码 | 说明 |
|------|------|------|------|
| 一段持续的范围 | **焦段** | `focus` | 取"焦段"而非"焦点"：焦点是一个点，焦段是一段范围 |
| 会话维度的范围 | **会话焦段** | `session_focus` | 一组同类对话 |
| 语义维度的范围 | **语义焦段** | `semantic_focus` | 一段话题 |
| 焦段下的对象 | **元素** | `element` | 中性词；不使用"成员" |

英文用 `focus` 而非 `state`：代码中 `state` 已占用两个含义（`agents.state` / `switch_state` 是在线状态，`state_stack` 是情景帧栈），语义级再称 `state` 会产生第三种含义，工具名也会与 `switch_state`、`list_states`、`push_state` 相撞。

## 三、两条轴

两条轴平行、正交，各自可多选、可空，均由 AI 自行选择。

| 轴 | 元素 | 例子 |
|------|------|------|
| 会话轴 | 具体会话、会话焦段 | 某个群、某个私信；所有聊天、所有私信、学生群 |
| 语义轴 | 语义焦段 | 化学教学、代码实现 |

一条记忆的适用范围 = 它锚定的元素集合，分三组记录，均可为空：

- `session_refs`：具体会话；
- `session_foci`：会话焦段；
- `semantic_foci`：语义焦段。

「只用于此状态」= 只锚具体会话；「作用于此类状态」= 锚会话焦段；两者同时锚定也允许。

## 四、会话焦段

- 平台预置一个会话焦段「所有聊天」，覆盖全部会话场景，判定时恒命中；它是"全局"的显式表达。
- 其余焦段由 AI 自建。
- **不按对话类型自动归档**：一个会话是否属于某焦段，由 AI 判断。它属于某段持续关系的一部分就归入；只是一次问答，就只算当前会话。
- 焦段名称可改。名称是检索与识别的凭据，应短、独立、不重复；相似或重复的焦段应合并，合并时可一并更新名称。

## 五、归属

- 默认只算当前会话，不自动挂任何会话焦段。
- 归入焦段是**显式动作**。
- 归属记录在会话帧上（帧的 `foci`），每轮随状态摘要复述给 AI，例如："你在 某群聊，属于焦段：所有聊天、学生群"。据此它不必每轮重新判断，也看得见当初为什么这么归。
- 可移出、可改挂，不锁死。

## 六、空集语义

一条记忆不锚任何元素时，适用范围为**当前会话 + 当前语义焦段**，工具必须同时给出警告：

> 未锚定焦段：这条记忆只在本会话与当前语义焦段下能被想起，换个地方就找不到了。要跨会话共享，请锚定焦段（例如「所有聊天」）。

据此不存在隐式全局；全局由显式锚定「所有聊天」表达。

## 七、记忆的类型与权值

### 7.1 类型

类型按情感陪伴定位，不照搬工程 agent 的分类：

| 类型 | 含义 | 默认权值 |
|------|------|---------|
| `person` | 人物：是谁、什么关系 | 5 |
| `relationship` | 关系变化 | 5 |
| `promise` | 约定：答应过什么 | 4 |
| `event` | 共同经历 | 3 |
| `preference` | 偏好 | 3 |
| `daily` | 日常流水 | 1 |

向量记忆与结构记忆**都**带类型与权值。

### 7.2 设定权值

设定权值 1-5，写入时由 AI 给定，此后不变（除非 AI 显式修改）。

| 权值 | 名称 | 存什么 | 随时间 |
|------|------|--------|--------|
| 5 | 核心 | 人物与关系定位、硬约束 | 几乎不消 |
| 4 | 重要 | 承诺、重要偏好、重大共同经历 | 淡出注入，保留可召回 |
| 3 | 一般 | 日常偏好、一般经历、阶段状态 | 同上 |
| 2 | 次要 | 一时的话题、临时信息 | 同上 |
| 1 | 流水 | 每条消息的自动记录 | 物理删除 |

### 7.3 时间权值

时间权值现算，不落库。两个输入先合成一个"主观时长"，再统一衰减一次——避免两个因子相乘造成的双重惩罚。

```
T        = max(Δ天, Δ调用 × 30 / 200)      # 200 次调用 ≈ 主观上过了 30 天
时间权值  = (1 + T / 30) ^ (-1)             # 反比例；T = 30 天时为半衰
```

- `Δ` 自**最近一次被召回**起算（不是创建时间）：常用记忆自然活得久，而设定权值一个字不改。
- 用反比例而非 `0.5^x`：幂律前期掉得快、后期长尾，符合遗忘曲线；指数是恒定半衰期，会"突然就没了"。幂律永不归零，正好靠阈值来淘汰。
- 一天之内大量调用同样触发衰减：一天 400 次调用 → T = 60 天 → 时间权值 1/3。

### 7.4 有效权重与两档处置

```
有效权重 = (设定权值 / 5) × 时间权值
阈值     = 0.1
```

| 设定权值 | 有效权重低于阈值时 | 可恢复 |
|---------|------------------|--------|
| 1（流水） | **物理删除**（DELETE，节约空间） | 否 |
| 2 及以上 | 不再自动注入、不再召回；库中保留 | 是，显式 `recall_memory` 仍可取回 |

按上式计算：权值 1 的记忆静默 30 天（或等效 200 次调用）即被删除；权值 2 约 90 天、权值 5 约 270 天后只是不再注入，记录保留。

物理删除由**定期批处理**执行（例如每日一次），不挂在读取路径上；读取路径只计算权重、决定注不注入。

## 八、注入

记忆是**补丁**，不是重播：只补上下文里还没有的，已注入过的条目不重复注入。

**位置**：插在 ledger（对话历史）**之前**——先想起这个人，再读他说的话。

**分家**：按"可见性是否依赖当前会话或当前焦段"决定放在哪一段。

| 记忆 | 位置 | 原因 |
|------|------|------|
| 不依赖当前会话与当前焦段的（锚「所有聊天」那类） | 锁定段，版本链冻结 | 任何会话看到的都一样，天然稳定 |
| 锚了具体会话 / 会话焦段 / 语义焦段的 | 尾部读数 | 随焦段切换变化，尾部打补丁即可 |

判据只有一条：可见性是否依赖当前会话或当前焦段。依赖的进尾部，不依赖的进前缀。这样焦段切换 = 尾部打一次补丁，前缀一个字节不动；也避免私信里的记忆名出现在群聊前缀里。

## 九、检索

- 任一元素命中即召回（或），命中元素多的排在前面。
- 不要求两轴同时命中：否则"群里讲过的化学"在私信里召不回来，与跨会话共享相悖。
- 「所有聊天」在全部会话场景命中，等价于显式全局。
- 语义轴为空时，跟随当下语义焦段：记忆写在哪个语义焦段下，就在那里可读。
- 召回结果按有效权重过滤；第 7.4 节判定为"不注入"的记忆不参与召回。

## 十、合并与整理

- 三个层次（具体会话、焦段、全局）对同一事实给出不同说法时，由 AI 整理记忆：改锚点、合并焦段、废弃过时的条目。
- **合并焦段前，必须列出两侧锚定的全部记忆**，交由 AI 阅读后再执行；合并与改名可在同一次操作里完成。
- 焦段不宜多、不宜相似：`list_focus` 的返回附此提示。

## 十一、与现有结构的关系

| 现有 | 关系 |
|------|------|
| `scope`（private / group / cross_user） | 语义是"谁能看见"，与本设计的"适用范围"正交，不动 |
| `state_stack` 会话帧 | 即会话级状态的载体；新增 `foci` 字段记录归属 |
| 帧上 `emotion` | 按现状保留：情绪仍挂会话帧，本次不改 |
| `cross_state_note` | 仍管临时约定 |
| `handoff.tail` | 仍管"刚才说到哪"（4 轮原文） |
| 结构记忆索引 | 走版本链冻结（`_build_memory_index`），本设计仅调整其内容来源，不改冻结机制 |
| `WorldAIMemory` | 世界侧另行对齐 |

两处与现设计相悖、且全仓无调用者的代码，本设计落地时一并处理：

| 位置 | 现状 | 处置 |
|------|------|------|
| `forgetting_mechanism.decay_memory` | 用 `value_score * 0.99` 写回权值，无调用者 | 删除或改写为"只算不落库" |
| `archive_low_value_memories` | 按标题相似度提升/丢弃，无调用者 | 改写为定期整理（合并与物理删除） |

## 十二、工具

| 工具 | 作用 |
|------|------|
| `switch_focus` | 切换、新建或改名焦段 |
| `list_focus` | 列出焦段，附"不宜多、相似者可合并改名"的提示 |
| `merge_focus` | 合并焦段；执行前列出两侧锚定的记忆 |
| `store_memory`（扩展） | 新增类型、权值、会话轴与语义轴锚点参数；锚点为空时按第六节警告 |
| `manage_records`（扩展） | 结构记忆同样带类型、权值与锚点 |
| `recall_memory`（扩展） | 结果按有效权重过滤；被召回的条目刷新其时间基准 |

## 十三、落地顺序（原计划）

1. 两套记忆的表结构：类型、设定权值、锚点、最近一次召回时间；
2. 有效权重与时间基准的纯函数（单一来源），召回按它过滤；
3. 会话帧新增 `foci`，状态摘要复述归属；
4. 焦段三工具与预置「所有聊天」；
5. 注入位置移到 ledger 之前，并按第八节分家；
6. 定期整理任务替换两处死代码；
7. 空集警告与 `list_focus` 提示的文案统一。

以上七步可在评审后分批评审落地；第 3、5 步涉及提示词前缀，须在前缀缓存不变式下验收。
